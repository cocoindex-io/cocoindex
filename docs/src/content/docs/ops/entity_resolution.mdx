<Lang only="python">

The `cocoindex.ops.entity_resolution` package resolves a set of raw entity names into a deduplicated canonical map. It finds near-duplicate names via embedding similarity (FAISS), then asks a pair-resolver (typically an LLM) to confirm matches and pick the better canonical name.

</Lang>

<Lang only="rust">

The `cocoindex::entity_resolution` module resolves a set of raw entity names into a deduplicated canonical map. It finds near-duplicate names via embedding similarity, then asks a pair-resolver (typically an LLM) to confirm matches and pick the better canonical name.

</Lang>

## Basic usage

{/* Rust: examples/rust/conversation_to_knowledge/src/pipeline.rs (resolve_entities), src/clients.rs (context keys) */}
<LangTabs>
<Fragment slot="python">

```python
import cocoindex as coco
from cocoindex.ops.entity_resolution import resolve_entities
from cocoindex.ops.entity_resolution.llm_resolver import LlmPairResolver
from cocoindex.ops.sentence_transformers import SentenceTransformerEmbedder

EMBEDDER = coco.ContextKey[SentenceTransformerEmbedder]("embedder", detect_change=True)
LLM_MODEL = coco.ContextKey[str]("llm_model", detect_change=True)

@coco.fn(memo=True)
async def resolve_my_entities(raw_entities: set[str]) -> dict[str, str | None]:
    result = await resolve_entities(
        entities=raw_entities,
        embedder=coco.use_context(EMBEDDER),
        resolve_pair=LlmPairResolver(model=coco.use_context(LLM_MODEL)),
    )
    return result.to_dict()
```

</Fragment>
<Fragment slot="rust">

```rust
use std::collections::HashMap;

use cocoindex::entity_resolution;
use cocoindex::ops::api::{ApiChatClient, LlmPairResolver};
use cocoindex::ops::sentence_transformers::SentenceTransformerEmbedder;
use cocoindex::prelude::*;

// LLM used to confirm entity-resolution pairs. Each decision's memo key holds
// the model, so no change detection on the key is needed.
cocoindex::context_key!(pub static RESOLVER_LLM: ApiChatClient);

// Local embedder for entity-resolution similarity.
cocoindex::context_key!(
    pub static EMBEDDER: SentenceTransformerEmbedder,
    detect_change
);

#[cocoindex::function(memo)]
pub async fn resolve_entities(
    ctx: &Ctx,
    kind: &String,
    names: &Vec<String>,
) -> Result<HashMap<String, Option<String>>> {
    let embedder = ctx.get_key(&EMBEDDER)?;
    let resolver = LlmPairResolver::with_client(ctx.get_key(&RESOLVER_LLM)?.clone())
        .with_entity_type(kind.as_str());
    let resolved = entity_resolution::resolve_entities(
        ctx,
        names,
        embedder,
        &resolver,
        None,
        entity_resolution::ResolveOptions::default(),
    )
    .await?;
    Ok(resolved.to_map().into_iter().collect())
}
```

`resolve_entities(&ctx, entities, &embedder, &resolve_pair, is_existing_canonical, options)` takes every argument positionally: the entities (any iterable of strings), an `EntityEmbedder`, a `PairResolver`, an optional existing-canonical predicate, and a `ResolveOptions`. The `Ctx` is passed through to the embedder and the resolver, so both memoize and batch through the engine.

</LangTabs>

## Existing-canonical handling

If some entity names are already established as canonical (e.g., they have on-disk files or database records), you can pass `is_existing_canonical` to influence how matches involving those names are resolved.

### Without `is_existing_canonical` (default)

The resolver decides which side becomes canonical on every match. No special treatment for any name.

### With `is_existing_canonical`

<Lang only="python">

Pass a sync predicate that returns `True` for names you consider already-established canonicals. The `existing_policy` parameter controls how strongly that status is enforced:

#### `PINNED` (default)

</Lang>

<Lang only="rust">

Pass a predicate that returns `true` for names you consider already-established canonicals. The `existing_policy` field of `ResolveOptions` controls how strongly that status is enforced:

#### `Pinned` (default)

</Lang>

Existing canonicals are immutable. They are seeded directly as canonicals without consulting the resolver. Two existings never merge. Non-existing entities are resolved in a second pass; if they match an existing canonical, the existing always wins.

Each event includes:
- `entity` / `canonical` — the entity and its resolved canonical
- `candidates` — what was passed to the resolver (empty if no resolver call)
- `decision` — the resolver's raw verdict (compare with `canonical` to detect policy overrides)
- `repointed` — if a prior canonical was demoted, its name
- `seeded` — <Lang only="python">`True`</Lang><Lang only="rust">`true`</Lang> for pinned existing-canonical entities seeded without resolver

## `resolve_entities` parameters

<Lang only="python">

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `entities` | `Iterable[str]` | *(required)* | Raw entity names. Duplicates collapsed; iterated in sorted order. |
| `embedder` | [`Embedder`](../common_resources/data_types#embedder) | *(required)* | Async single-text embedder. `LiteLLMEmbedder` and `SentenceTransformerEmbedder` both work. |
| `resolve_pair` | `PairResolver` | *(required)* | Pair-resolution callback. See [`LlmPairResolver`](#llmpairresolver) for the built-in option. |
| `is_existing_canonical` | `Callable[[str], bool] \| None` | `None` | Sync predicate for existing-canonical detection. |
| `existing_policy` | `ExistingCanonicalPolicy` | `PINNED` | How to treat existing canonicals. Ignored when `is_existing_canonical` is `None`. |
| `on_resolution` | `Callable[[ResolutionEvent], None] \| None` | `None` | Sync callback fired once per entity after resolution finishes, in deterministic per-policy order. |
| `max_distance` | `float` | `0.3` | Cosine distance threshold (similarity >= 0.7). |
| `top_n` | `int` | `5` | Max candidates surfaced per entity. |

</Lang>

<Lang only="rust">

The parameters, in order:

| Parameter | Type | Default |
|-----------|------|---------|
| `ctx` | `&Ctx` | *(required)* |
| `entities` | `impl IntoIterator<Item = impl AsRef<str>>` | *(required)*; duplicates collapsed, iterated in sorted order |
| `embedder` | `&impl EntityEmbedder` (any [`Embedder`](../common_resources/data_types#embedder)) | *(required)* |
| `resolve_pair` | `&impl PairResolver` | *(required)* |
| `is_existing_canonical` | `Option<&(dyn Fn(&str) -> bool + Sync)>` | `None` |
| `options` | `ResolveOptions { existing_policy, max_distance, top_n }` | `ResolveOptions::default()`: `Pinned`, `0.3`, `5` |
| `on_resolution` (`resolve_entities_with_events` only) | `Option<&(dyn Fn(&ResolutionEvent) + Sync)>` | `None` |

`max_distance` is the cosine distance threshold (similarity >= 0.7 at the default `0.3`), and `top_n` is the maximum number of candidates surfaced per entity. `existing_policy` is ignored when `is_existing_canonical` is `None`.

</Lang>

## `LlmPairResolver`

<Lang only="python">

`cocoindex.ops.entity_resolution.llm_resolver` provides `LlmPairResolver`, a built-in resolver that uses an LLM (via [litellm](https://docs.litellm.ai/)) to decide pair matches. It sends each `(entity, candidates)` pair to the model and returns a structured decision — with automatic validation and retry when the model hallucinates a name not in the candidate list.

</Lang>

<Lang only="rust">

`cocoindex::ops::api` provides `LlmPairResolver`, a built-in resolver that uses an LLM to decide pair matches. It sends each `(entity, candidates)` pair to the model and returns a structured decision — with automatic validation and retry when the model hallucinates a name not in the candidate list. It calls an OpenAI-compatible `/chat/completions` endpoint through [`ApiChatClient`](/docs/rust/ops/model_apis/#chat-and-structured-extraction), in JSON mode.

</Lang>

<RustNote>
The resolver does not use litellm or `instructor`: it asks the endpoint for a JSON-object response and parses it. The prompt, the validation and the retry behavior are the same as in Python.
</RustNote>

Uses the same litellm model-string format as [`LiteLLMEmbedder`](./litellm):

| Provider | Example |
|----------|---------|

### Validation and retry

After each LLM call, the response is validated:

1. **Structural**: the JSON response must parse into the expected schema
2. **Semantic**: `matched` (if non-null) must be in the supplied `candidates`. If not, the LLM is re-prompted with explicit feedback and the conversation continues

The default retry budget is 2. If exhausted, no match is returned.

### Memoization

<Lang only="python">

Each unique `(entity, candidates)` pair's decision is persisted across runs via [`@coco.fn(memo=True)`](../programming_guide/function). Changing the model or prompt invalidates the cache. No additional memoization wrapper is needed.

</Lang>

<Lang only="rust">

Each unique `(entity, candidates)` pair's decision is [memoized](../programming_guide/function) through the `ctx` the resolver receives, and persists across runs. The memo key holds the model, base URL, entity type and extra guidance, so changing the model or prompt invalidates the cache; `retries` is absent, since it cannot change a valid decision. No additional memoization wrapper is needed.

</Lang>

## Custom resolvers

For cases where the built-in `LlmPairResolver` doesn't fit (rule-based matching, different LLM framework, etc.), implement the `PairResolver` <Lang only="python">protocol</Lang><Lang only="rust">trait</Lang>:

{/* Rust: rust/sdk/cocoindex/tests/entity_resolution.rs (ScriptedResolver), PairDecision constructors from rust/sdk/cocoindex/src/entity_resolution.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.ops.entity_resolution import PairResolver, PairDecision, CanonicalSide

class MyResolver:
    async def __call__(self, entity: str, candidates: list[str]) -> PairDecision:
        # `candidates` is a non-empty, de-duplicated list of canonical names
        # with cosine similarity to `entity` above the threshold.

        # No match:
        return PairDecision()

        # Match — existing candidate stays canonical (default):
        return PairDecision(matched="Microsoft")

        # Match — new entity is the better canonical name:
        return PairDecision(matched="Microsoft Corp.", canonical=CanonicalSide.NEW)
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::{CanonicalSide, Ctx, PairDecision, PairResolver, async_trait};

struct MyResolver;

#[async_trait]
impl PairResolver for MyResolver {
    async fn resolve_pair(
        &self,
        _ctx: &Ctx,
        entity: &str,
        candidates: &[String],
    ) -> cocoindex::Result<PairDecision> {
        // `candidates` is a non-empty, de-duplicated list of canonical names
        // with cosine similarity to `entity` above the threshold.

        // No match:
        Ok(PairDecision::no_match())

        // Match — existing candidate stays canonical (default):
        // Ok(PairDecision::matched("Microsoft"))

        // Match — new entity is the better canonical name:
        // Ok(PairDecision::matched_with("Microsoft Corp.", CanonicalSide::New))
    }
}
```

`resolve_pair` also receives the `Ctx`, so a resolver can memoize through the engine as `LlmPairResolver` does. It may run concurrently across components.

</Fragment>
</LangTabs>

<Lang only="python">

Any async callable with the signature `(entity: str, candidates: list[str]) -> PairDecision` works — no subclassing required.

</Lang>

`PairDecision.canonical` is advisory: the `existing_policy` may override it (see [Existing-canonical handling](#existing-canonical-handling)).
