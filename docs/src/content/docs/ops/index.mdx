CocoIndex ships a set of built-in operations under the `cocoindex.ops` package.
Each module is independently importable and composes with the rest of a pipeline.

{/* Rust: module paths from rust/sdk/cocoindex/src/ops/mod.rs and src/lib.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.ops import text, litellm, sentence_transformers, entity_resolution
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::entity_resolution;
use cocoindex::ops::{api, sentence_transformers, text};
```

In the Rust SDK each `cocoindex::ops` module sits behind a Cargo feature of the `cocoindex` crate, so the heavy dependencies (tree-sitter grammars, the ONNX runtime, an HTTP client) are only built when used. `cocoindex::entity_resolution` needs no feature.

</Fragment>
</LangTabs>

## Operation modules

| Module | What it provides | Rust |
|---|---|---|
| [Text operations](/docs/ops/text/) | Code language detection, regex-based `SeparatorSplitter`, and syntax-aware `RecursiveSplitter` (tree-sitter) returning position-tracked [`Chunk`](/docs/common_resources/data_types/#chunk)s. | `cocoindex::ops::text`, feature `text` |
| [Sentence Transformers](/docs/ops/sentence_transformers/) | Local text embeddings via `sentence-transformers`, with model caching, thread-safe GPU access, and optional normalization. | `cocoindex::ops::sentence_transformers`, feature `fastembed` (runs the ONNX models through `fastembed`) |
| [LiteLLM](/docs/ops/litellm/) | Embeddings and audio transcription through LiteLLM's unified API across 100+ providers (OpenAI, Azure, Vertex AI, Bedrock, Cohere, and more). | `cocoindex::ops::api`, feature `embed_api`: `ApiEmbedder` and `ApiTranscriber` over an OpenAI-compatible HTTP API, not LiteLLM |
| [Entity resolution](/docs/ops/entity_resolution/) | Deduplicate entity names via FAISS embedding similarity plus a pluggable LLM pair-resolver, with PINNED / PREFERRED canonical policies. | `cocoindex::entity_resolution`, no feature needed; `LlmPairResolver` in `cocoindex::ops::api` |

## Most common: chunking code and text

The most-used built-in is `RecursiveSplitter`. It does syntax-aware splitting that
respects language structure (functions, classes, blocks) via tree-sitter, falling
back to separator-based splitting for unsupported languages.

{/* Rust: examples/rust/code_embedding/src/main.rs (process_file) */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.ops.text import RecursiveSplitter

splitter = RecursiveSplitter()

chunks = splitter.split(
    python_code,
    chunk_size=1000,
    min_chunk_size=300,
    chunk_overlap=300,
    language="python",
)
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::ops::text::{RecursiveChunkConfig, RecursiveSplitter};

let splitter = RecursiveSplitter::new()?;

let chunks = splitter.split_with(
    &text,
    RecursiveChunkConfig {
        chunk_size: 1000,
        min_chunk_size: Some(300),
        chunk_overlap: Some(300),
        language: Some("python".to_string()),
    },
);
```

</Fragment>
</LangTabs>

It tries to keep each output chunk between `min_chunk_size` and `chunk_size`, splitting
at the highest-level boundary that fits and descending to finer boundaries when a piece
is still too large. See [Text operations](/docs/ops/text/) for the full parameter reference,
supported languages, and custom-language configuration.

## Embeddings

Two interchangeable embedding backends are available, both providing a
`VectorSchemaProvider` so vector columns are configured automatically by connectors:

- [Sentence Transformers](/docs/ops/sentence_transformers/) runs locally, no API key.
- [LiteLLM](/docs/ops/litellm/) reaches hosted providers behind one API.

The Rust SDK has the same two: `SentenceTransformerEmbedder` (local, through `fastembed`) and `ApiEmbedder` (any OpenAI-compatible endpoint). Both implement `VectorSchemaProvider` and the [`Embedder`](/docs/common_resources/data_types/#embedder) trait.
