## As source

The connector provides three read helpers:

- `list_blobs()` lists blobs in a container, with optional prefix and filtering.
- `get_blob()` fetches a single blob by name.
- `read()` reads blob content directly by name.

<Lang only="python">

All helpers take an async Azure `ContainerClient`. Create and close the client in your app lifespan.

</Lang>

<Lang only="rust">

All helpers take the connector's own `azure_blob::ContainerClient`, a handle to one container built with `ContainerClient::new(account_url, container_name, credential)`.

</Lang>

### Connection setup

<Lang only="python">Use Azure's SDK authentication methods directly. For local development, `DefaultAzureCredential` can use your Azure CLI login:</Lang><Lang only="rust">The `credential` is a `Credential`: an Entra ID token the client gets and renews itself, a SAS token, a storage account access key, or a bearer token you obtained. For local development, `TokenCredential::Default` can use your Azure CLI login:</Lang>

`TokenCredential::Default` takes the sources of the Azure SDK's `DefaultAzureCredential` that need no interactive sign-in. It uses the first source that is configured where the process runs, a service principal from `AZURE_TENANT_ID`, `AZURE_CLIENT_ID` and `AZURE_CLIENT_SECRET`, the managed identity of the Azure resource the process runs on, or the account signed in with `az login`. `TokenCredential::ClientSecret { tenant_id, client_id, client_secret }`, `TokenCredential::ManagedIdentity { client_id }` (`None` for the system-assigned identity) and `TokenCredential::AzureCli` name one source. The client gets the token on the first request and renews it shortly before it expires. `Credential::BearerToken` takes an access token for the `https://storage.azure.com/` resource that you obtained yourself, such as the one `az account get-access-token --resource https://storage.azure.com/` prints, and does not renew it.

### list_blobs

List blobs in an Azure Blob Storage container. Returns an `AzureBlobWalker`<Lang only="python"> that supports async iteration</Lang>.

{/* Rust: rust/sdk/cocoindex/src/connectors/azure_blob.rs */}
<LangTabs>
<Fragment slot="python">

```python
def list_blobs(
    container_client: ContainerClient,
    *,
    prefix: str = "",
    path_matcher: FilePathMatcher | None = None,
    max_file_size: int | None = None,
) -> AzureBlobWalker
```

</Fragment>
<Fragment slot="rust">

```rust
pub fn list_blobs(client: &ContainerClient, options: ListOptions) -> AzureBlobWalker

pub struct ListOptions {
    /// Only list blobs in this folder.
    pub prefix: String,
    /// Filter by relative path (after prefix stripping). Defaults to match-all.
    pub path_matcher: Option<Arc<dyn FilePathMatcher>>,
    /// Skip blobs larger than this many bytes.
    pub max_file_size: Option<u64>,
}

pub async fn AzureBlobWalker::list(&self) -> Result<Vec<AzureBlobFile>>
pub async fn AzureBlobWalker::items(&self) -> Result<Vec<(String, AzureBlobFile)>>
```

`ListOptions::default()` lists the whole container. The walker is not an iterator: `list()` returns every matching blob, and `items()` the `(key, file)` pairs for `mount_each!`.

</Fragment>
</LangTabs>

**Parameters:**

- `container_client` - <Lang only="python">An async Azure `ContainerClient`.</Lang><Lang only="rust">The `ContainerClient` (the argument is named `client`).</Lang>
- `prefix` - Only list blobs in this folder. A prefix names a folder: `"docs"` and `"docs/"` both list the blobs under `docs/`, and neither lists `docsa.md`. The folder is stripped from relative paths in returned files. To select blobs by the start of their name (for example `2024-*.csv`), use `path_matcher`.
- `path_matcher` - Optional filter for files. Patterns are matched against the relative path after prefix stripping. See [PatternFilePathMatcher](../common_resources/data_types#patternfilepathmatcher).
- `max_file_size` - Skip blobs larger than this size in bytes.

**Returns:** An `AzureBlobWalker` <Lang only="python">that can be used with `async for` loops.</Lang><Lang only="rust">whose `list()` and `items()` list the container once each time you call them.</Lang>

### Filtering files

Use `PatternFilePathMatcher` to include or exclude blobs by glob pattern. Patterns are matched against the relative path after prefix stripping:

{/* Rust: examples/rust/azure_blob_embedding/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.connectors import azure_blob
from cocoindex.resources.file import PatternFilePathMatcher

matcher = PatternFilePathMatcher(included_patterns=["**/*.md"])

async for file in azure_blob.list_blobs(client, prefix="docs/", path_matcher=matcher):
    process(file)
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::resources::file::PatternFilePathMatcher;

let files = azure_blob::list_blobs(
    client,
    ListOptions {
        prefix,
        path_matcher: Some(Arc::new(
            PatternFilePathMatcher::include(["**/*.md"])
                .map_err(|e| Error::engine(format!("matcher: {e}")))?,
        )),
        ..Default::default()
    },
)
.list()
.await?;
```

`PatternFilePathMatcher::new(included, excluded)` takes exclude patterns too.

### AzureBlobFilePath

Each file returned by the connector has an `AzureBlobFilePath`, a [`FilePath`](../common_resources/data_types#filepath) specialized for Azure Blob Storage:

<Lang only="python">

- **Relative path** (`file.file_path.path`) - The blob name relative to the walker prefix, or the full blob name if no prefix was used.
- **Resolved path** (`file.file_path.resolve()`) - The full blob name in the container.
- **Identity** - Two `AzureBlobFilePath`s are equal only if they have the same account, container and relative name.

For example, with `prefix="docs/"` and blob name `"docs/readme.md"`:

- `file.file_path.path` returns `PurePath("readme.md")`
- `file.file_path.resolve()` returns `"docs/readme.md"`

A derived path (`parent`, `/`, `with_name()`, `with_suffix()`) resolves to the blob name of the new path in the same folder: `file.file_path.with_suffix(".txt").resolve()` returns `"docs/readme.txt"`.

</Lang>

<Lang only="rust">

- **Relative path** (`file.file_path().path()`, a `&str`) - The blob name relative to the walker prefix, or the full blob name if no prefix was used. `file.key()` returns it as a `String`, the key for `mount_each!`.
- **Resolved path** (`file.file_path().resolve()`, also `blob_name()`) - The full blob name in the container.
- **Account and container** (`account_name()`, `container_name()`).
- **Identity** - The memo key is `(account_name, container_name, relative_path)`.

For example, with `prefix: "docs/"` and blob name `"docs/readme.md"`:

- `file.file_path().path()` returns `"readme.md"`
- `file.file_path().resolve()` returns `"docs/readme.md"`

`AzureBlobFile` has the public fields `size`, `modified_secs` and `etag`, plus `key()`, `read()`, `read_size(n)` and `read_text()`; it implements `FileLike` and `MemoInput`. Its memo key holds only stable metadata, never the client.

</Lang>

<RustNote>
`AzureBlobFilePath` has no derived-path methods (`parent`, `/`, `with_name()`, `with_suffix()`).
</RustNote>

### Example

{/* Rust: examples/rust/azure_blob_embedding/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
import cocoindex as coco
from cocoindex.connectors import azure_blob
from cocoindex.resources.file import FileLike, PatternFilePathMatcher

@coco.fn
async def app_main() -> None:
    client = coco.use_context(AZURE_CONTAINER_CLIENT)
    matcher = PatternFilePathMatcher(included_patterns=["**/*.md"])
    files = azure_blob.list_blobs(client, prefix="docs/", path_matcher=matcher)

    with coco.component_subpath("file"):
        async for key, file in files.items():
            await coco.mount(coco.component_subpath(key), process_file, file)

@coco.fn(memo=True)
async def process_file(file: FileLike[str]) -> None:
    text = await file.read_text()
    # Process the file content.
```

</Fragment>
<Fragment slot="rust">

```rust
use std::sync::Arc;

use cocoindex::connectors::azure_blob::{self, AzureBlobFile, ContainerClient, ListOptions};
use cocoindex::prelude::*;
use cocoindex::resources::file::PatternFilePathMatcher;

cocoindex::context_key!(static CONTAINER: ContainerClient);

#[cocoindex::function(memo)]
async fn process_file(_ctx: &Ctx, file: AzureBlobFile) -> Result<()> {
    let text = file.read_text().await?;
    // Process the file content.
    Ok(())
}

async fn app_main(ctx: Ctx, prefix: String) -> Result<()> {
    let client = ctx.get_key(&CONTAINER)?;
    let files = azure_blob::list_blobs(
        client,
        ListOptions {
            prefix,
            path_matcher: Some(Arc::new(
                PatternFilePathMatcher::include(["**/*.md"])
                    .map_err(|e| Error::engine(format!("matcher: {e}")))?,
            )),
            ..Default::default()
        },
    )
    .list()
    .await?;

    mount_each!(
        files.into_iter().map(|f| (f.key(), f)),
        |file| process_file(ctx, file)
    )
    .await?;
    Ok(())
}
```
