The `zvec` connector writes documents to [zvec](https://zvec.org), an embedded, in-process vector database. zvec runs inside your application (no server or daemon) and stores each collection in a directory on disk.

## Connection setup

### connect

`connect()` creates a `ManagedConnection` rooted at a base directory. Each collection lives in a subdirectory under it.

{/* Rust: rust/sdk/cocoindex/src/connectors/zvec.rs, tests/zvec_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
def connect(base_path: str | Path, *, enable_mmap: bool = True) -> ManagedConnection
```

</Fragment>
<Fragment slot="rust">

```rust
pub fn connect(base_path: impl AsRef<Path>, options: ConnectOptions) -> Result<ManagedConnection>

pub struct ConnectOptions {
    /// Whether zvec uses memory-mapped I/O for data files. Defaults to `true`.
    pub enable_mmap: bool,
}

let conn = zvec::connect(tempdir.path().join("zvec"), ConnectOptions::default())?;
```

</Fragment>
</LangTabs>

**Parameters:**

- `base_path` — Directory under which collections are stored. Created if missing.
- `enable_mmap` — Whether zvec uses memory-mapped I/O for data files.

### ManagedConnection

A handle to the base directory. zvec takes an exclusive write lock per open collection, so `ManagedConnection` caches open handles by collection name and reuses them.

**Methods:**

- `collection_path(name)` — Path to a collection's directory.
- `close()` — Release all open collection handles (drops their write locks).

The Rust `ManagedConnection` has the same two methods, `collection_path(name)` and `close().await`, plus `base_path()` and `open_existing(name).await`, which returns a cached `zvec_rust::Collection` handle for queries. Drop that handle before a run that destroys the collection.

For a lifespan, use `managed_connection()`, which closes handles on exit:

```python
def managed_connection(
    base_path: str | Path, *, enable_mmap: bool = True
) -> Iterator[ManagedConnection]
```

The Rust SDK has no `managed_connection()`: call `conn.close().await?` on shutdown.

## As target

The `zvec` connector tracks which documents should exist in a collection and automatically handles upserts and deletions. zvec's native upsert is used directly, and documents are removed by id when they are no longer declared.

### Declaring target states

#### Setting up a connection

Create a `ContextKey[zvec.ManagedConnection]` to identify your connection, then provide it in your lifespan:

:::note
The key name is load-bearing across runs — it's the stable identity CocoIndex uses to track managed documents. See [ContextKey as stable identity](../programming_guide/context#contextkey-as-stable-identity) before renaming.
:::

{/* Rust: rust/sdk/cocoindex/tests/zvec_target.rs, rust/sdk/SHOWCASE.md (verified against zvec.rs) */}

<Fragment slot="python">

```python
import cocoindex as coco

ZVEC_DB = coco.ContextKey[zvec.ManagedConnection]("main_db")

@coco.lifespan
def coco_lifespan(builder: coco.EnvironmentBuilder) -> Iterator[None]:
    with zvec.managed_connection("./zvec_data") as conn:
        builder.provide(ZVEC_DB, conn)
        yield
```

</Fragment>

Declares a collection as a target state. Returns a `CollectionTarget` for declaring documents.

</Fragment>


`declare_collection_target` returns a handle whose documents resolve when the current component commits; `mount_collection_target(...).await?` returns a handle that accepts documents at once.

</Fragment>
</LangTabs>

**Parameters:**

- `db` — A `ContextKey[ManagedConnection]` identifying the connection.
- `collection_name` — Name of the collection (a subdirectory under the connection's base path).
- `schema` — Schema definition (see [Collection schema](#collection-schema-from-python-class)).
- `managed_by` — Whether CocoIndex manages the collection lifecycle (`"system"`, creating and destroying it) or assumes it already exists (`"user"`, documents only).

**Returns:** A pending `CollectionTarget`. Use `await zvec.mount_collection_target(ZVEC_DB, collection_name, schema)` to resolve.

### Collection schema: from Python class

Define the collection structure using a Python class (dataclass, NamedTuple, or Pydantic model):

{/* Rust: rust/sdk/cocoindex/src/connectors/zvec.rs */}
<LangTabs>
<Fragment slot="python">

```python
@classmethod
async def CollectionSchema.from_class(
    cls,
    record_type: type[RowT],
    primary_key: list[str],
    *,
    column_overrides: dict[str, ZvecType | ZvecVectorDef | ZvecFtsType | VectorSchemaProvider] | None = None,
) -> CollectionSchema[RowT]
```

</Fragment>
<Fragment slot="rust">

```rust
impl CollectionSchema {
    pub fn from_row<T: SchemaFields>(
        primary_key: impl IntoIterator<Item = impl Into<String>>,
    ) -> Result<Self>

    pub fn with_vector_dim(self, column: &str, dim: usize) -> Result<Self>
    pub fn with_vector_def(self, column: &str, def: ZvecVectorDef) -> Result<Self>
    pub fn with_column_type(self, column: &str, zvec_type: ZvecType) -> Result<Self>
    pub fn with_fts(self, column: &str, fts: ZvecFtsType) -> Result<Self>
}
```

The Rust row type is a struct that derives `SchemaFields` (and `Serialize`). Python's `column_overrides` become builder calls on the derived schema: `with_vector_dim` for a vector dimension, `with_vector_def` for the index, `with_column_type` for a scalar type, `with_fts` for a full-text field. The zvec schema has no `with_vector_schema`; take the dimension from the embedder and pass it to `with_vector_dim`.

</Fragment>
</LangTabs>

**Parameters:**

- `record_type` — A record type whose fields define the document structure.
- `primary_key` — Exactly one column name. Its value becomes the document `id`.
- `column_overrides` — Optional per-column overrides for type mapping or vector configuration.

:::note[Single primary key]
zvec documents have a single string `id`, so `primary_key` must name exactly one column. Its value is converted to `str` to form the id. Composite primary keys are not supported.

Because the id is `str(value)`, some key types are ambiguous: in a union or `Any` column, `1` and `"1"` get the same id, and `bytes` become the text `b'...'`. Creating a new collection raises a `ValueError` when the key column is typed `Any`, `object`, a union or `bytes`. A collection that CocoIndex already tracks keeps working. Use a `str` or `int` key column, and convert the value yourself if needed.
:::

:::note[At least one vector field]
zvec is a vector database: every collection must declare at least one vector field (dense or sparse).
:::

**Example:**

{/* Rust: rust/sdk/cocoindex/tests/zvec_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from dataclasses import dataclass
from typing import Annotated
import numpy as np
from numpy.typing import NDArray
from cocoindex.resources.schema import VectorSchema

@dataclass
class Doc:
    id: str
    title: str
    year: int
    embedding: Annotated[NDArray[np.float32], VectorSchema(dtype=np.dtype(np.float32), size=384)]

schema = await zvec.CollectionSchema.from_class(Doc, primary_key=["id"])
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Clone, Serialize, SchemaFields)]
struct SimpleDoc {
    id: String,
    title: String,
    year: i64,
    #[coco(vector = 4)]
    embedding: Vec<f32>,
}

fn simple_schema() -> CollectionSchema {
    CollectionSchema::from_row::<SimpleDoc>(["id"]).unwrap()
}
```

`#[coco(vector = N)]` fixes the dimension in the struct; a bare `#[coco(vector)]` leaves it to `with_vector_dim`. The primary key must be one `String`, `Uuid` or integer column, and not an `Option`.

</Fragment>
</LangTabs>

Scalar Python types map to zvec field types as follows:

| Python Type | Rust Type | zvec `DataType` |
|-------------|-----------|-----------------|
| `bool` | `bool` | `BOOL` |
| `int` | `i64` (`i16`, `i32`: `INT32`) | `INT64` |
| `float` | `f64` (`f32`: `FLOAT`) | `DOUBLE` |
| `str` | `String` | `STRING` |
| `bytes` | `Vec<u8>` | `STRING` (base64) |
| `uuid.UUID` | `Uuid` | `STRING` |
| `decimal.Decimal` | `Decimal` | `STRING` |
| `datetime.date` / `time` / `datetime` | `NaiveDate`, `NaiveTime`, `DateTime` | `STRING` (ISO format) |
| `datetime.timedelta` | `Duration` | `DOUBLE` (total seconds) |
| `list[str]` / `list[int]` / `list[float]` / `list[bool]` | (no Rust counterpart; see below) | `ARRAY_STRING` / `ARRAY_INT64` / `ARRAY_DOUBLE` / `ARRAY_BOOL` |
| other `list`, `dict`, nested structs | other `Vec<T>`, maps, nested structs, `#[coco(json)]` | `STRING` (JSON) |
| `NDArray` (with vector schema) | `Vec<f32>` with `#[coco(vector)]` | `VECTOR_FP32` (float32) or `VECTOR_FP16` (float16) |

Scalar fields get an invert index by default so they can be used in query filters. The primary-key column maps to the document `id` and is not stored as a separate field. The Rust SDK stores every `Vec<T>` other than `Vec<u8>` and a vector as a JSON string: it has no `ARRAY_*` mapping. It writes `float32` dense vectors only: a `#[coco(vector = N, half)]` field is an error, because the `zvec-rust` bindings have no float16 setter. For smaller storage, keep a float32 vector and set `quantize`.

#### ZvecType

Override the scalar type, encoder, or indexing for a field:

{/* Rust: rust/sdk/cocoindex/tests/zvec_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from typing import Annotated
import zvec
from cocoindex.connectors.zvec import ZvecType

@dataclass
class MyRow:
    id: str
    # Store as INT32 instead of INT64, without a filter index.
    count: Annotated[int, ZvecType(zvec.DataType.INT32, indexed=False)]
    embedding: Annotated[NDArray[np.float32], VectorSchema(dtype=np.dtype(np.float32), size=384)]
```

</Fragment>
<Fragment slot="rust">

```rust
// Store `small` as INT32 instead of the derived type, without a filter index.
let schema = CollectionSchema::from_row::<TypedDoc>(["id"])?.with_column_type(
    "small",
    ZvecType {
        data_type: ScalarType::Int32,
        indexed: false,
    },
)?;
```

`ScalarType` has `Bool`, `Int32`, `Int64`, `Uint32`, `Uint64`, `Float`, `Double` and `String`. A `#[coco(type = "int32")]` attribute on the field selects the type too (the names are case-insensitive), but keeps the index. Python's encoder has no counterpart: put `#[serde(serialize_with = "…")]` on the field.

</Fragment>
</LangTabs>

#### ZvecFtsType

Mark a `str` field as full-text (FTS) indexed. The field is stored as a `STRING` field with a zvec FTS index, so you can run full-text match queries against it directly through zvec. Requires zvec >= 0.5.

{/* Rust: rust/sdk/cocoindex/tests/zvec_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from typing import Annotated
from cocoindex.connectors.zvec import ZvecFtsType

@dataclass
class Doc:
    id: str
    body: Annotated[str, ZvecFtsType(tokenizer_name="standard", filters=("lowercase",))]
    embedding: Annotated[NDArray[np.float32], VectorSchema(dtype=np.dtype(np.float32), size=384)]
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Clone, Serialize, SchemaFields)]
struct FtsDoc {
    id: String,
    body: String,
    #[coco(vector = 4)]
    embedding: Vec<f32>,
}

let schema =
    CollectionSchema::from_row::<FtsDoc>(["id"])?.with_fts("body", ZvecFtsType::default())?;
```

`ZvecFtsType` has the fields `tokenizer_name` (default `"standard"`), `filters` (default `["lowercase"]`) and `extra_params`.

</Fragment>
</LangTabs>

`ZvecFtsType` options: `tokenizer_name` (e.g. `"standard"`, `"jieba"`), `filters` (token filters applied after tokenization, default `("lowercase",)`), and `extra_params`. The connector writes the field and its FTS index; querying it (for example with `zvec.Query(field_name=..., fts=zvec.Fts(match_string=...))`) happens directly against zvec, since this connector only handles the write path. In Rust, query through `conn.open_existing(name).await?` and the re-exported `zvec_rust` API.

### Vectors

A collection can declare multiple named vector fields, dense and sparse, in one schema. zvec supports querying across them with reranking at read time.

#### Dense vectors

A NumPy `ndarray` field with a `VectorSchema` becomes a dense vector. The element dtype selects the zvec type: `float32` → `VECTOR_FP32`, `float16` → `VECTOR_FP16`. zvec's dense index only accepts these two; for smaller storage, keep a float32 vector and set `quantize`. Tune the HNSW index with `ZvecVectorDef`:

{/* Rust: rust/sdk/cocoindex/tests/zvec_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.connectors.zvec import ZvecVectorDef

@dataclass
class Doc:
    id: str
    embedding: Annotated[
        NDArray[np.float32],
        VectorSchema(dtype=np.dtype(np.float32), size=384),
        ZvecVectorDef(metric="cosine", quantize="int8"),
    ]
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Clone, Serialize, SchemaFields)]
struct VectorDoc {
    id: String,
    #[coco(vector)]
    embedding: Vec<f32>,
    #[coco(vector = 2)]
    small: Option<Vec<f32>>,
}

let schema = CollectionSchema::from_row::<VectorDoc>(["id"])?
    .with_vector_dim("embedding", 3)?
    .with_vector_def(
        "embedding",
        ZvecVectorDef {
            metric: VectorMetric::L2,
            quantize: Some(VectorQuantize::Int8),
        },
    )?;
```

`VectorMetric` has `Cosine` (default), `Ip` and `L2`; `quantize` is `None` or `Some(VectorQuantize::Fp16 | Int8 | Int4)`.

</Fragment>
</LangTabs>

`ZvecVectorDef` options: `metric` (`"cosine"`, `"ip"`, `"l2"`) and `quantize` (`"none"`, `"fp16"`, `"int8"`, `"int4"`).

#### Sparse vectors

Mark a `dict[int, float]` field (mapping dimension → weight) as sparse with `ZvecVectorDef(sparse=True)`. The Rust SDK has no sparse vectors: the `zvec-rust` bindings have no document setter for them, so the Rust connector writes float32 dense vectors only.

```python
@dataclass
class Doc:
    id: str
    sparse: Annotated[dict[int, float], ZvecVectorDef(sparse=True)]
```

## Full example

{/* Rust: rust/sdk/SHOWCASE.md (verified against zvec.rs and tests/zvec_target.rs) */}
<LangTabs>
<Fragment slot="python">

```python
import pathlib
from dataclasses import dataclass
from typing import Annotated, Iterator

import cocoindex as coco
import numpy as np
from numpy.typing import NDArray
from cocoindex.connectors import zvec
from cocoindex.resources.schema import VectorSchema

ZVEC_DB = coco.ContextKey[zvec.ManagedConnection]("main_db")


@dataclass
class Doc:
    id: str
    title: str
    embedding: Annotated[
        NDArray[np.float32], VectorSchema(dtype=np.dtype(np.float32), size=384)
    ]


@coco.lifespan
def coco_lifespan(builder: coco.EnvironmentBuilder) -> Iterator[None]:
    with zvec.managed_connection("./zvec_data") as conn:
        builder.provide(ZVEC_DB, conn)
        yield


@coco.fn
async def index_docs(docs: list[Doc]) -> None:
    target = await zvec.mount_collection_target(
        ZVEC_DB,
        "docs",
        await zvec.CollectionSchema.from_class(Doc, primary_key=["id"]),
    )
    for doc in docs:
        target.declare_row(row=doc)
```

```rust
cocoindex::context_key!(static ZVEC: ManagedConnection);

struct Doc {
```
