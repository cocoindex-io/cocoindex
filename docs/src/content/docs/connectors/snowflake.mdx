The `snowflake` connector provides target state APIs for writing rows to Snowflake tables. CocoIndex tracks the rows that should exist and applies table creation, upserts, updates, and deletes incrementally.

{/* Rust: examples/rust/snowflake_target/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.connectors import snowflake
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::snowflake::{
    self, SnowflakeConfig, SnowflakeConnection, SnowflakeTableOptions, TableSchema,
};
```

The module is compiled with the `snowflake` Cargo feature of the `cocoindex` crate. Snowflake has no official Rust client, so the connector speaks the HTTP protocol of the official connectors directly: a password login that yields a session token, then statements with server-side `?` bindings.

</Fragment>
</LangTabs>

<Lang only="python">

:::note[Install]
Install the optional Snowflake dependency before using this connector:

```bash
pip install "cocoindex[snowflake]"
```
:::

</Lang>

{/* Rust: examples/rust/snowflake_target/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
import os
from collections.abc import Iterator

import cocoindex as coco
from cocoindex.connectors import snowflake

SNOWFLAKE = coco.ContextKey[snowflake.ConnectionConfig]("snowflake")

@coco.lifespan
def coco_lifespan(builder: coco.EnvironmentBuilder) -> Iterator[None]:
    builder.provide(
        SNOWFLAKE,
        snowflake.ConnectionConfig(
            account=os.environ["SNOWFLAKE_ACCOUNT"],
            user=os.environ["SNOWFLAKE_USER"],
            password=os.environ["SNOWFLAKE_PASSWORD"],
            warehouse=os.environ.get("SNOWFLAKE_WAREHOUSE"),
            role=os.environ.get("SNOWFLAKE_ROLE"),
        ),
    )
    yield
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::snowflake::{SnowflakeConfig, SnowflakeConnection};

cocoindex::context_key!(static SNOWFLAKE: SnowflakeConnection, key = "snowflake_demo");

let mut config = SnowflakeConfig::new(
    required("SNOWFLAKE_ACCOUNT")?,
    required("SNOWFLAKE_USER")?,
    required("SNOWFLAKE_PASSWORD")?,
)
.warehouse(env_or("SNOWFLAKE_WAREHOUSE", "COCOINDEX_DEMO_WH"));
if let Some(role) = std::env::var("SNOWFLAKE_ROLE")
    .ok()
    .filter(|v| !v.is_empty())
{
    config = config.role(role);
}
let conn = SnowflakeConnection::new(config);
let app = cocoindex::Environment::builder()
    .db_path(".cocoindex_db")
    .provide_key(&SNOWFLAKE, conn)
    .build()
    .await?
    .app("SnowflakeTarget")
    .await?;
```

`SnowflakeConnection::new(config)` makes no request until the first statement. Each batch of statements logs in, runs and closes its own session. The connection is cheap to clone; `conn.query(sql).await?` runs a statement in a fresh session and returns its rows as JSON objects keyed by column name.

## As target

The `snowflake` connector provides target state APIs for writing rows to tables.

### Tables

Declares a table as a target state. Returns a `TableTarget` for declaring rows.

```rust
    options: SnowflakeTableOptions,

pub struct SnowflakeTableOptions {
    /// Database holding the table (created if missing). `None` uses the session's current database.
    pub database: Option<String>,
    /// Schema holding the table (created if missing). `None` uses the session's current schema.
    pub schema: Option<String>,
    pub managed_by: ManagedBy,
}
```

`declare_table_target*` declares the table in the current component; its rows resolve when the component commits. `mount_table_target*` mounts the table first, so you can declare rows at once. `table_target` and `table_target_with_options` build the table target state without declaring it.

</Fragment>
</LangTabs>

**Parameters:**

- <Lang only="python">`db` - A `ContextKey[ConnectionConfig]`</Lang><Lang only="rust">`conn` - A `&ContextKey<SnowflakeConnection>`</Lang> identifying the connection to use.
- `table_name` - Name of the table.
- `table_schema` - Schema definition including columns and primary key.
- `database` - Optional Snowflake database name.
- `schema` - Optional Snowflake schema name.
- `managed_by` - Whether CocoIndex manages the table lifecycle (<Lang only="python">`"system"`</Lang><Lang only="rust">`ManagedBy::System`, the default</Lang>) or assumes it exists (<Lang only="python">`"user"`</Lang><Lang only="rust">`ManagedBy::User`</Lang>).

When <Lang only="python">`managed_by="system"`</Lang><Lang only="rust">`managed_by` is `ManagedBy::System`</Lang>, CocoIndex creates the database, schema, and table if needed. Table changes use Snowflake DDL, and row changes use `MERGE` for upserts.

<Lang only="rust">

A batch of row changes runs in one session: rows are `MERGE`d and deleted by primary key in statements of up to 4,000 bindings each, so a batch takes a few statements, not one per row.

</Lang>

## Table schema: from a Rust struct

Define the table structure using a Rust struct that derives `SchemaFields`:

</Lang>

{/* Rust: examples/rust/snowflake_target/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
from dataclasses import dataclass

@dataclass
class ProductRow:
    id: str
    name: str
    price: float
    metadata: dict[str, object]

schema = await snowflake.TableSchema.from_class(
    ProductRow,
    primary_key=["id"],
)
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::prelude::*;
use serde::{Deserialize, Serialize};
use serde_json::Value as JsonValue;

#[derive(Clone, Serialize, Deserialize, SchemaFields)]
struct SnowflakeOrder {
    order_id: String,
    customer: String,
    quantity: i64,
    unit_price: f64,
    #[coco(json)]
    attributes: JsonValue,
}

let schema = TableSchema::from_row::<SnowflakeOrder>(["order_id"])?;
```

`TableSchema::from_row::<Row>(primary_key)` takes the primary-key columns as an iterator of names. A `serde_json::Value` field needs `#[coco(json)]`; a `Vec<T>`, map or nested struct maps to `VARIANT` on its own.

</Fragment>
</LangTabs>

<Lang only="python">

Python types are automatically mapped to Snowflake column types:

| Python Type | Snowflake Type |
|-------------|----------------|
| `bool` | `BOOLEAN` |
| `int` | `NUMBER` |
| `float` | `FLOAT` |
| `decimal.Decimal` | `NUMBER` |
| `str` | `VARCHAR` |
| `bytes` | `BINARY` |
| `uuid.UUID` | `VARCHAR` |
| `datetime.date` | `DATE` |
| `datetime.time` | `TIME` |
| `datetime.datetime` | `TIMESTAMP_TZ` |
| `datetime.timedelta` | `NUMBER` |
| `list`, `dict`, nested structs | `VARIANT` |

`VARIANT` values are JSON-serialized and written with `PARSE_JSON`.

</Lang>
<Lang only="rust">

Rust types are automatically mapped to Snowflake column types:

| Rust Type | Snowflake Type |
|-----------|----------------|
| `bool` | `BOOLEAN` |
| `i16`, `i32`, `i64` (and the unsigned widths) | `NUMBER` |
| `f32`, `f64` | `FLOAT` |
| `rust_decimal::Decimal` | `NUMBER` |
| `String` | `VARCHAR` |
| `Vec<u8>` | `BINARY` |
| `uuid::Uuid` | `VARCHAR` |
| `chrono::NaiveDate` | `DATE` |
| `chrono::NaiveTime` | `TIME` |
| `chrono::DateTime`, `chrono::NaiveDateTime` | `TIMESTAMP_TZ` |
| `std::time::Duration` | `NUMBER` |
| other `Vec<T>`, maps, nested structs, `#[coco(json)]` | `VARIANT` |
| `#[coco(vector)] Vec<f32>` | `ARRAY` |

`VARIANT` and `ARRAY` values are JSON-serialized and written with `PARSE_JSON`. An `Option<T>` field is a nullable column; every other field is `NOT NULL`.

</Lang>

### Custom column types

Use `#[coco(type = "…")]` to specify a custom Snowflake type:

</Lang>

{/* Rust: rust/sdk/cocoindex/tests/snowflake_target.rs; #[coco(type)] from rust/sdk/cocoindex_macros/src/lib.rs */}
<LangTabs>
<Fragment slot="python">

```python
from dataclasses import dataclass
from typing import Annotated

from cocoindex.connectors.snowflake import SnowflakeType

@dataclass
class ProductRow:
    id: Annotated[int, SnowflakeType("NUMBER(38, 0)")]
    embedding: Annotated[list[float], SnowflakeType("ARRAY")]
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Serialize, SchemaFields)]
struct ProductRow {
    #[coco(type = "NUMBER(38, 0)")]
    id: i64,
    #[coco(type = "ARRAY")]
    embedding: Vec<f64>,
}
```

`#[coco(type = "…")]` sets the column type verbatim. A value is written as it serializes with serde; for another form, put `#[serde(serialize_with = "…")]` on the field. Explicit columns are also possible with `TableSchema::new(columns, primary_key)?` and `ColumnDef::new("VARIANT").parse_json()`; a `ColumnDef` is nullable unless `.not_null()` is called.

</Fragment>
</LangTabs>

<Lang only="python">

You can also pass `column_overrides` when constructing the schema:

</Lang>
<Lang only="rust">

You can also replace the type of one column on the derived schema, for this schema only. `with_column_type` keeps the column's derived nullability and takes the `parse_json` flag of the `ColumnDef` you pass:

</Lang>

```python
from dataclasses import dataclass

@dataclass
class ProductRow:
    id: str
    name: str
    price: float
    metadata: dict[str, object]

async def declare_products(rows: list[ProductRow]) -> None:
    table = await snowflake.mount_table_target(
        SNOWFLAKE,
        table_name="product_index",
        table_schema=await snowflake.TableSchema.from_class(
            ProductRow,
            primary_key=["id"],
        ),
        database="ANALYTICS",
        schema="PUBLIC",
    )

    for row in rows:
        table.declare_row(row=row)
```

## Identifier handling

Database, schema, table, and column names must be simple Snowflake identifiers containing letters, numbers, and underscores, and must not start with a number. The connector quotes identifiers when generating SQL.
