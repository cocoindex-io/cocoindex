## Connection setup

### DorisConnectionConfig

Configure the connection to your Doris cluster:

{/* Rust: rust/sdk/cocoindex/tests/doris_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.connectors import doris

config = doris.DorisConnectionConfig(
    fe_host="localhost",
    database="my_database",
    fe_http_port=8080,
    query_port=9030,
    username="root",
    password="",
)
```

</Fragment>
<Fragment slot="rust">

```rust
let mut cfg = DorisConfig::new(fe_host, database)
    .fe_http_port(http_port)
    .query_port(query_port);
if let Ok(user) = std::env::var("DORIS_USERNAME") {
    cfg = cfg.username(user);
}
if let Ok(pw) = std::env::var("DORIS_PASSWORD") {
    cfg = cfg.password(pw);
}
```

`DorisConfig::new(fe_host, database)` sets the defaults of the table below; the builder methods `fe_http_port`, `query_port`, `username`, `password`, `enable_https`, `be_load_host`, `replication_num`, `buckets` and `batch_size` change them. The fields are public too.

</Fragment>
</LangTabs>

**Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `fe_host` | `str` | *(required)* | Frontend host address |
| `database` | `str` | *(required)* | Database name |
| `fe_http_port` | `int` | `8080` | Frontend HTTP port (for stream load) |
| `query_port` | `int` | `9030` | MySQL-compatible query port |
| `username` | `str` | `"root"` | Username |
| `password` | `str` | `""` | Password |
| `enable_https` | `bool` | `False` | Use HTTPS for stream load |
| `be_load_host` | `str \| None` | `None` | Override backend host for stream load (defaults to `fe_host`) |
| `batch_size` | `int` | `10000` | Max rows per stream load batch |
| `stream_load_timeout` | `int` | `600` | Timeout (seconds) for stream load |
| `replication_num` | `int` | `1` | Replication factor for new tables |
| `buckets` | `int \| str` | `"auto"` | Bucket count for new tables |

The Rust `DorisConfig` has the same fields with the same defaults (`buckets` is a `String`), plus `max_retries` (`3`), `retry_base_delay` (`1.0`) and `retry_max_delay` (`30.0`) seconds for Stream Load retries.

## As target

The `doris` connector provides target state APIs for writing rows to tables. CocoIndex tracks what rows should exist and automatically handles upserts and deletions via Doris stream load.

### Declaring target states

#### Setting up a connection

Create a `ContextKey[doris.ManagedConnection]` to identify your connection, then provide it in your lifespan:

:::note
The key name is load-bearing across runs — it's the stable identity CocoIndex uses to track managed rows. See [ContextKey as stable identity](../programming_guide/context#contextkey-as-stable-identity) before renaming.

CocoIndex tracks each table by the `ContextKey` and the table name. The `database` in `DorisConnectionConfig` is not part of that identity. If you change `database` under the same key, CocoIndex treats it as if you moved the tables there. It assumes that they already exist in the new database, so it does not create them, and it leaves the old database as it is. To write to a new, empty database, use a new `ContextKey`.
:::

{/* Rust: rust/sdk/cocoindex/tests/doris_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
import cocoindex as coco
from cocoindex.connectors import doris

DORIS_DB = coco.ContextKey[doris.ManagedConnection]("my_doris")

@coco.lifespan
def coco_lifespan(builder: coco.EnvironmentBuilder) -> Iterator[None]:
    conn = doris.connect(doris.DorisConnectionConfig(
        fe_host="localhost",
        database="my_database",
    ))
    builder.provide(DORIS_DB, conn)
    yield
    # conn is cleaned up after yield
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::doris::{DorisConfig, DorisConnection};

cocoindex::context_key!(static DORIS_DB: DorisConnection, key = "doris_target_test_db");

let conn = DorisConnection::connect(cfg).await?;
let app = Environment::builder()
    .db_path(&db)
    .provide_key(&DORIS_DB, conn.clone())
    .build()
    .await?
    .app("DorisInvertedIndex")
    .await?;
```

`context_key!` declares the key. Its stable name is the identifier, or the `key = "…"` string when given. `provide_key(&DORIS_DB, conn)` provides the connection, in a `#[cocoindex::lifespan]` function or on `Environment::builder()` as here. The Rust connection's identity excludes the `database` in the same way.

#### Tables (parent state)

Declares a table as a target state. Returns a `DorisTableTarget` for declaring rows.

{/* Rust: rust/sdk/cocoindex/src/connectors/doris.rs */}
<LangTabs>
<Fragment slot="python">

```python
def declare_table_target(
    db: ContextKey[ManagedConnection],
    table_name: str,
    table_schema: TableSchema[RowT],
    *,
    managed_by: Literal["system", "user"] = "system",
    vector_indexes: list[VectorIndexDef] | None = None,
    inverted_indexes: list[InvertedIndexDef] | None = None,
) -> DorisTableTarget[RowT, coco.PendingS]
```

</Fragment>
<Fragment slot="rust">

```rust
pub async fn mount_table_target(
    ctx: &Ctx,
    conn: &ContextKey<DorisConnection>,
    table_name: impl Into<String>,
    table_schema: TableSchema,
) -> Result<TableTarget>

pub async fn mount_table_target_with_options(
    ctx: &Ctx,
    conn: &ContextKey<DorisConnection>,
    table_name: impl Into<String>,
    table_schema: TableSchema,
    options: DorisTableOptions,
) -> Result<TableTarget>

pub struct DorisTableOptions {
    pub managed_by: ManagedBy,
    pub vector_indexes: Vec<VectorIndexDef>,
    pub inverted_indexes: Vec<InvertedIndexDef>,
}
```

The handle type is `TableTarget`. `managed_by`, `vector_indexes` and `inverted_indexes` go in `DorisTableOptions`. `declare_table_target` and `declare_table_target_with_options` take the same arguments and return a handle whose rows resolve when the current component commits.

</Fragment>
</LangTabs>

**Parameters:**

- `db` — A `ContextKey[doris.ManagedConnection]` identifying the connection to use.
- `table_name` — Name of the table.
- `table_schema` — Schema definition including columns and primary key (see [Table schema](#table-schema-from-python-class)).
- `managed_by` — Whether CocoIndex manages the table lifecycle (`"system"`) or assumes it exists (`"user"`).
- `vector_indexes` — Optional list of vector index definitions (see [Vector indexes](#vector-indexes)).
- `inverted_indexes` — Optional list of inverted index definitions (see [Inverted indexes](#inverted-indexes)).

**Returns:** A pending `DorisTableTarget`. Use the convenience wrapper `await doris.mount_table_target(...)` to resolve.

### Table schema: from Python class

Define the table structure using a Python class:

{/* Rust: rust/sdk/cocoindex/src/connectors/doris.rs */}
<LangTabs>
<Fragment slot="python">

```python
@classmethod
async def TableSchema.from_class(
    cls,
    record_type: type[RowT],
    primary_key: list[str],
    *,
    column_overrides: dict[str, DorisType | VectorSchemaProvider] | None = None,
) -> TableSchema[RowT]
```

</Fragment>
<Fragment slot="rust">

```rust
impl TableSchema {
    pub fn from_row<T: SchemaFields>(
        primary_key: impl IntoIterator<Item = impl Into<String>>,
    ) -> Result<Self>

    pub fn with_vector_dim(self, field_name: &str, dim: usize) -> Result<Self>
    pub async fn with_vector_schema(
        self,
        field_name: &str,
        provider: &(impl VectorSchemaProvider + ?Sized),
    ) -> Result<Self>
    pub fn with_column_type(self, field_name: &str, doris_type: impl Into<String>) -> Result<Self>
}
```

The Rust row type is a struct that derives `SchemaFields` (and `Serialize`). Python's `column_overrides` become builder calls on the derived schema: `with_vector_schema` or `with_vector_dim` for a vector column, `with_column_type` for a type override.

</Fragment>
</LangTabs>

**Parameters:**

- `record_type` — A record type whose fields define table columns.
- `primary_key` — List of column names forming the primary key.
- `column_overrides` — Optional per-column overrides for type mapping or vector configuration.

**Example:**

{/* Rust: rust/sdk/cocoindex/tests/schema_from_row.rs, rust/sdk/SHOWCASE.md (verified against doris.rs) */}
<LangTabs>
<Fragment slot="python">

```python
@dataclass
class DocEmbedding:
    id: int
    text: str
    embedding: Annotated[NDArray, embedder]

schema = await doris.TableSchema.from_class(
    DocEmbedding,
    primary_key=["id"],
)
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Clone, Serialize, Deserialize, SchemaFields)]
struct DocEmbedding {
    id: i64,
    text: String,
    #[coco(vector)]
    embedding: Vec<f32>,
}

let schema = doris::TableSchema::from_row::<DocEmbedding>(["id"])?
    .with_vector_schema("embedding", ctx.get_key(&EMBEDDER)?)
    .await?;
```

`#[coco(vector)]` marks an `ARRAY<FLOAT>` vector column whose dimension is set with `with_vector_dim` or `with_vector_schema`; `#[coco(vector = 384)]` fixes it in the struct. `Option<T>` fields become nullable columns.

</Fragment>
</LangTabs>

Python types are automatically mapped to Doris types:

| Python Type | Rust Type | Doris Type |
|-------------|-----------|------------|
| `bool` | `bool` | `BOOLEAN` |
| `int` | `i16`, `i32`, `i64` | `BIGINT` |
| `float` | `f32`, `f64` | `DOUBLE` |
| `str` | `String` | `STRING` (Rust: `TEXT`) |
| `bytes` | `Vec<u8>` | `STRING` (base64) |
| `uuid.UUID` | `Uuid` | `VARCHAR(36)` |
| `datetime.datetime` | `DateTime`, `NaiveDateTime` | `DATETIME` (Rust: `DATETIME(6)`) |
| `datetime.date` | `NaiveDate` | `DATE` |
| `list`, `dict`, nested structs | other `Vec<T>`, maps, nested structs, `#[coco(json)]` | `JSON` |
| `NDArray` (with vector schema) | `Vec<f32>` with `#[coco(vector)]` | `ARRAY<FLOAT>` |

The Rust mapping also covers `NaiveTime` (`VARCHAR(20)`), `Decimal` (`TEXT`) and `Duration` (`BIGINT`).

`bytes` values are intentionally base64-encoded before writing to `STRING` so arbitrary binary data survives Doris's JSON Stream Load path.

#### DorisType

Use `DorisType` to specify a custom Doris type:

{/* Rust: rust/sdk/cocoindex/src/row_schema.rs, rust/sdk/cocoindex/src/connectors/doris.rs (with_column_type) */}
<LangTabs>
<Fragment slot="python">

```python
from typing import Annotated
from cocoindex.connectors.doris import DorisType

@dataclass
class MyRow:
    id: Annotated[int, DorisType("INT")]
    value: Annotated[float, DorisType("FLOAT")]
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Serialize, SchemaFields)]
struct MyRow {
    #[coco(type = "INT")]
    id: i64,
    #[coco(type = "FLOAT")]
    value: f64,
}
```

Or on the derived schema, for this schema only: `TableSchema::from_row::<MyRow>(["id"])?.with_column_type("value", "FLOAT")?`. `#[coco(type = "…")]` applies to every connector the struct is used with.

</Fragment>
</LangTabs>

### Vector indexes

Doris supports vector similarity search via HNSW and IVF indexes. Define them with `VectorIndexDef`:

{/* Rust: rust/sdk/cocoindex/src/connectors/doris.rs */}
<LangTabs>
<Fragment slot="python">

```python
from cocoindex.connectors.doris import VectorIndexDef

vector_idx = VectorIndexDef(
    field_name="embedding",
    index_type="HNSW",       # or "IVF"
    metric_type="l2_distance",  # or "cosine_distance"
)
```

</Fragment>
<Fragment slot="rust">

```rust
pub struct VectorIndexDef {
    pub field_name: String,
    pub index_type: String,   // "HNSW" (default) or "IVF"
    pub metric_type: String,  // "l2_distance" (default), "inner_product", "cosine_distance"
    pub max_degree: Option<u32>,
    pub ef_construction: Option<u32>,
    pub nlist: Option<u32>,
}

impl VectorIndexDef {
    pub fn new(field_name: impl Into<String>) -> Self
    pub fn index_type(self, index_type: impl Into<String>) -> Self
    pub fn metric_type(self, metric: impl Into<String>) -> Self
    pub fn max_degree(self, v: u32) -> Self
    pub fn ef_construction(self, v: u32) -> Self
    pub fn nlist(self, v: u32) -> Self
}
```

`VectorIndexDef::new("embedding")` is an HNSW index with `l2_distance`; the builder methods change the rest. Pass the list in `DorisTableOptions::vector_indexes`.

</Fragment>
</LangTabs>

**Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `field_name` | `str` | *(required)* | Column to index |
| `index_type` | `str` | `"HNSW"` | Index type: `"HNSW"` or `"IVF"` |
| `metric_type` | `str` | `"l2_distance"` | Distance metric: `"l2_distance"` or `"cosine_distance"` |
| `max_degree` | `int \| None` | `None` | HNSW max degree |
| `ef_construction` | `int \| None` | `None` | HNSW construction parameter |
| `nlist` | `int \| None` | `None` | IVF number of partitions |

#### connect_async

Create an async MySQL connection for running queries:

```python
async def connect_async(
    fe_host: str,
    query_port: int = 9030,
    username: str = "root",
    password: str = "",
    database: str | None = None,
) -> Any  # aiomysql connection
```

The Rust SDK has no `connect_async`: `DorisConnection::pool()` returns the `sqlx::MySqlPool` the connection already holds, and queries run on it.
