The `oci_object_storage` connector provides utilities for reading objects from Oracle Cloud Infrastructure (OCI) Object Storage buckets, with an optional [live mode](../programming_guide/live_mode) driven by OCI Object Storage events delivered through OCI Streaming.

## As source

The connector provides three ways to read from OCI Object Storage:

<Lang only="python">

- `list_objects()` — List and iterate over objects in a bucket (with optional prefix and filtering)
- `get_object()` — Fetch a single object by its name
- `read()` — Read object content directly without first fetching metadata

All require an `oci.object_storage.ObjectStorageClient`, which you create and manage yourself. The OCI SDK is synchronous; this connector wraps SDK calls with `asyncio.to_thread`, so the public API remains async.

</Lang>

<Lang only="rust">

- `list_objects()` — List the objects in a bucket (with optional prefix and filtering); `list_objects_live()` adds live mode
- `OciClient::get_object()` — Fetch a single object's metadata by its name
- `OciClient::read()` — Read the content of an object

All take an `OciClient`, which you create and provide yourself.

</Lang>

`OciClient::connect()` reads an API-key profile from `~/.oci/config` (or `OCI_CONFIG_FILE`), profile `DEFAULT` (or `OCI_PROFILE` / `OCI_CLI_PROFILE`). `OciClient::from_config(OciConfig { tenancy, user, fingerprint, key_file, region, pass_phrase })?` takes the profile's values directly; `OciConfig::from_file(path, profile)?` parses one. The private key is a PKCS#8 or PKCS#1 PEM; a profile with a `pass_phrase` opens an encrypted PKCS#8 key (`BEGIN ENCRYPTED PRIVATE KEY`, as `oci setup config` writes one). A key in the legacy OpenSSL encryption (`Proc-Type: 4,ENCRYPTED`) is rejected: re-encode it with `openssl pkcs8 -topk8`.

To run as the compute instance itself (an instance principal), build the client with `OciClient::from_instance_principal()`:

```rust
let oci = OciClient::from_instance_principal().await?;
```

It exchanges the instance's certificate from the metadata service for a session token and renews the token as it expires. The instance must be in a dynamic group with a policy that lets it read the bucket. `from_instance_principal_with_options(InstancePrincipalOptions { metadata_base_url, federation_endpoint })` sets the two endpoints explicitly; `OCI_METADATA_BASE_URL` also overrides the metadata endpoint.

An `OciClient` is `Clone` and has no `close()`. Its stable identity (`state_id()`) comes from the region, never from the credentials.

### list_objects

List objects in an OCI Object Storage bucket. Returns an `OCIWalker` that supports async iteration.

```python
    client: ObjectStorageClient,
    namespace: str,
    bucket_name: str,
    *,
    prefix: str = "",
    path_matcher: FilePathMatcher | None = None,
    max_file_size: int | None = None,
    live_stream: LiveStream[bytes] | None = None,

```

</Fragment>
<Fragment slot="rust">

```rust
pub fn list_objects(
    client: &OciClient,
    namespace: impl Into<String>,
    bucket: impl Into<String>,
    options: ListOptions,
) -> OciWalker

pub struct ListOptions {
    /// Only list objects whose name starts with this prefix.
    pub prefix: String,
    /// Filter by relative path (after prefix stripping). Defaults to match-all.
    pub path_matcher: Option<Arc<dyn FilePathMatcher>>,
    /// Skip objects larger than this many bytes.
    pub max_file_size: Option<u64>,
}

pub async fn OciWalker::list(&self) -> Result<Vec<OciFile>>
pub async fn OciWalker::items(&self) -> Result<Vec<(String, OciFile)>>
```

The walker is not an iterator: `list()` returns every matching object, and `items()` the `(key, file)` pairs for `mount_each!`. The Rust prefix is passed to OCI as given, so `"data"` also matches `database.csv`: name a folder with its trailing slash, `"data/"`. Live mode is a separate function, `list_objects_live` (see [Live bucket watching](#live-bucket-watching)).

</Fragment>
</LangTabs>

<Lang only="python">

**Parameters:**

- `client` — An `oci.object_storage.ObjectStorageClient`.
- `namespace` — The OCI Object Storage namespace.
- `bucket_name` — The bucket name.
- `prefix` — Only list objects in this folder. A prefix names a folder: `"data"` and `"data/"` both list the objects under `data/`, and neither lists `database.csv`. The folder is stripped from relative paths in the returned files. To select objects by the start of their name (for example `2024-*.csv`), use `path_matcher`. Live mode applies the same folder.
- `path_matcher` — Optional filter for files. Patterns are matched against the relative path (after prefix stripping). See [PatternFilePathMatcher](../common_resources/data_types#patternfilepathmatcher).
- `max_file_size` — Skip objects larger than this size in bytes.
- `live_stream` — Optional `LiveStream[bytes]` of OCI Object Storage event payloads. When provided, `OCIWalker.items()` returns a [`LiveMapView`](../advanced_topics/live_component#livemapfeed-and-livemapview) that performs an initial scan and continues watching for changes via the supplied stream. See [Live mode](#live-bucket-watching).

**Returns:** An `OCIWalker` that can be used with `async for` loops.

</Lang>

**Parameters:**

- `client` — An `OciClient`.
- `namespace` — The OCI Object Storage namespace.
- `bucket` — The bucket name.
- `options.prefix` — Only list objects whose name starts with this prefix. The prefix is stripped from the relative paths of the returned files.

### OciFilePath

</Lang>

<Lang only="python">

Each file returned by the connector has an `OCIFilePath` — a [`FilePath`](../common_resources/data_types#filepath) specialized for OCI Object Storage:

- **Relative path** (`file.file_path.path`) — The object name relative to the walker prefix (or the full name if no prefix was used).
- **Resolved path** (`file.file_path.resolve()`) — The full OCI object name (the value passed to `head_object` / `get_object`).
- **Namespace and bucket** — `file.file_path.namespace`, `file.file_path.bucket_name`.
- **Identity** — Two `OCIFilePath`s are equal only if they have the same namespace, bucket and relative name.

For example, with `prefix="data/"` and an object named `"data/docs/readme.md"`:
- `file.file_path.path` → `PurePath("docs/readme.md")`
- `file.file_path.resolve()` → `"data/docs/readme.md"`

A derived path (`parent`, `/`, `with_name()`, `with_suffix()`) resolves to the object name of the new path in the same folder: `file.file_path.with_suffix(".txt").resolve()` → `"data/docs/readme.txt"`.

</Lang>

<Lang only="rust">

Each file returned by the connector has an `OciFilePath` (`file.file_path()`):

- **Relative path** (`path()`, a `&str`) — The object name relative to the walker prefix (or the full name if no prefix was used).
- **Resolved path** (`resolve()`) — The full OCI object name.
- **Namespace and bucket** — `namespace()`, `bucket()`.

For example, with prefix `"data/"` and an object named `"data/docs/readme.md"`, `path()` is `"docs/readme.md"` and `resolve()` is `"data/docs/readme.md"`.

</Lang>

<RustNote>
`OciFilePath` has no derived-path methods (`parent`, `/`, `with_name()`, `with_suffix()`). `OciFile` has the public fields `size`, `modified_secs` and `etag`, plus `key()`, `read()`, `read_size(n)` and `read_text()`; it implements `FileLike` and `MemoInput`.
</RustNote>

### Live bucket watching

<Lang only="python">

When `live_stream` is provided, `items()` returns a [`LiveMapView`](../advanced_topics/live_component#livemapfeed-and-livemapview) instead of a plain `AsyncIterable`. Combined with [`mount_each()`](../programming_guide/processing_component#mount_each), this enables automatic incremental bucket watching — newly created, updated, and deleted objects are processed without a full rescan.

The typical setup uses **OCI Streaming**. Configure an [OCI Events Rule](https://docs.oracle.com/en-us/iaas/Content/Events/Concepts/eventsoverview.htm) that forwards Object Storage events (`createobject`, `updateobject`, `deleteobject`) to an OCI Streaming stream, then consume that stream as a `LiveStream[bytes]` via the Kafka connector — see [`topic_as_stream()` and `payloads()`](./kafka#as-a-live-stream) for the consumer / stream setup — and pass it as `live_stream`:

</Lang>

<Lang only="rust">

`list_objects_live()` returns an `OciLiveWalker`, a [`LiveMapFeed`](../advanced_topics/live_component#livemapfeed-and-livemapview) of `OciFile`s. Combined with `ctx.mount_each_live`, this enables automatic incremental bucket watching — newly created, updated, and deleted objects are processed without a full rescan.

The typical setup uses **OCI Streaming**. Configure an [OCI Events Rule](https://docs.oracle.com/en-us/iaas/Content/Events/Concepts/eventsoverview.htm) that forwards Object Storage events (`createobject`, `updateobject`, `deleteobject`) to an OCI Streaming stream, then consume that stream as a `LiveStream<Vec<u8>>` via the Kafka connector — see [`topic_as_stream()` and `payloads()`](./kafka#as-a-live-stream) for the consumer / stream setup — and pass it as `events`:

<Fragment slot="rust">

```rust
use cocoindex::connectors::kafka;
use cocoindex::connectors::oci_object_storage::{ListOptions, OciFile, list_objects_live};

let consumer = kafka::KafkaConsumer::connect_with_options(
    &["<oci-streaming-bootstrap-host>:9092"],
    kafka::KafkaConsumerOptions {
        consumer_group: Some("my-group".to_string()),
        ..Default::default()
    },
)
.await?;
let events = kafka::topic_as_stream(&consumer, ["object-storage-events"]).payloads();

let feed = list_objects_live(
    &client,
    "my-namespace",
    "my-bucket",
    ListOptions::default(),
    events,
);
ctx.mount_each_live(&"objects", feed, move |_ctx, file: OciFile| {
    async move {
        let text = file.read_text().await?;
        // ...
        Ok(())
    }
})
.await
```

`events` is any `LiveStream<Vec<u8>>` of raw OCI event JSON payloads, one event per item, such as the Kafka connector's `topic_as_stream(..).payloads()`. Each event is confirmed with a `HEAD` of the object: a present object is an update, a `404` a delete. The walker acknowledges each event to the stream once the object it names has synced (at once when the event is filtered out), so a consumer group's committed offset never passes an unprocessed event.

`OciLiveWalker::logic_version(version)` opts into skipping the startup scan on a rerun whose recorded version matches, and relies on the durable stream to replay the backlog. Bump the version whenever the processing logic changes.

</Fragment>
</LangTabs>

See [Live Mode](../programming_guide/live_mode) for how live mode works and how to enable it on the app.

### Example

{/* Rust: examples/rust/oci_object_storage_embedding/src/main.rs (one-shot listing, no live mode) */}
<LangTabs>
<Fragment slot="python">

```python
import pathlib

from confluent_kafka.aio import AIOConsumer
import oci
from oci.object_storage import ObjectStorageClient

import cocoindex as coco
from cocoindex.connectors import kafka, oci_object_storage, localfs
from cocoindex.resources.file import FileLike, PatternFilePathMatcher


@coco.fn(memo=True)
async def process_file(file: FileLike[str], target: localfs.DirTarget) -> None:
    text = await file.read_text()
    target.declare_file(filename=file.file_path.path.as_posix(), content=text)


@coco.fn
async def app_main(
    namespace: str, bucket: str, outdir: pathlib.Path,
) -> None:
    target = await localfs.mount_dir_target(outdir)

    config = oci.config.from_file()
    client = ObjectStorageClient(config)

    consumer = AIOConsumer({
        "bootstrap.servers": "<oci-streaming-host>:9092",
        "group.id": "my-group",
        "enable.auto.commit": "false",
    })
    topic_stream = kafka.topic_as_stream(consumer, ["object-storage-events"])

    matcher = PatternFilePathMatcher(included_patterns=["**/*.md"])
    walker = oci_object_storage.list_objects(
        client, namespace, bucket,
        prefix="docs/",
        path_matcher=matcher,
        live_stream=topic_stream.payloads(),
    )

    await coco.mount_each(process_file, walker.items(), target)


app = coco.App(
    coco.AppConfig(name="OCIToFiles"),
    app_main,
    namespace="my-namespace",
    bucket="my-bucket",
    outdir=pathlib.Path("./out"),
)
app.update_blocking(live=True)
```

```rust
cocoindex::context_key!(static OCI: OciClient);

async fn app_main(ctx: Ctx, namespace: String, bucket: String, prefix: String) -> Result<()> {
    let files = oci_object_storage::list_objects(
        ctx.get_key(&OCI)?,
        &namespace,
        &bucket,
        ListOptions {
            prefix,
            path_matcher: Some(Arc::new(
                PatternFilePathMatcher::include(["**/*.md"])
                    .map_err(|e| Error::engine(format!("matcher: {e}")))?,
            )),
            ..Default::default()
        },
    )
    .list()
    .await?;

    mount_each!(
        files.into_iter().map(|f| (f.key(), f)),
        |file| process_file(ctx, file)
    )
    .await?;
    Ok(())
}
```
