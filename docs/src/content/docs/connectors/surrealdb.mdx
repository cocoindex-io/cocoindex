## Connection setup

Create a `ConnectionFactory` and provide it via a `ContextKey`. It holds connection parameters and opens one authenticated connection per event loop, shared by all tables and batches. Call `await factory.close()` at shutdown (in the lifespan, after `yield`) to close it.

:::note
The key name is load-bearing across runs — it's the stable identity CocoIndex uses to track managed rows. See [ContextKey as stable identity](../programming_guide/context#contextkey-as-stable-identity) before renaming.
:::

{/* Rust: examples/rust/conversation_to_knowledge/src/main.rs and src/clients.rs */}

```python
        url="ws://localhost:8000/rpc",
        namespace="test",
        database="test",
```

```rust
use cocoindex::connectors::surrealdb::Graph;
use cocoindex::prelude::*;

#[tokio::main]
async fn main() -> Result<()> {
```

`Graph::connect(url, ns, db, user, pass)` opens one WebSocket connection and signs in as a root user. `url` is the host and port, without the `ws://` scheme or `/rpc` path. A `Graph` has no `close()` method; `builder.on_shutdown(..)` in a `#[cocoindex::lifespan]` function is the place for teardown.

## As target

The `surrealdb` connector provides target state APIs for writing records to normal tables and relation tables. CocoIndex tracks what records should exist and automatically handles upserts and deletions.

Writes are sent as typed parameters (`datetime`, `date`, `Decimal`, `UUID`, `bytes`, `timedelta`, lists and dicts arrive as native SurrealDB types, not strings).

**Transactions and errors.** The changes of each table are applied in chunks of at most 500 actions, each chunk one transaction (`Transaction conflict` errors are retried with backoff). Atomicity is per chunk, not across tables. Any statement error rolls the chunk back and raises, so the update fails and the affected components are retried on the next run.

**Record IDs** may be a string, an integer, or a tuple/list, which becomes an array ID (`person:['sap', '0001']`). Relation endpoints (`from_id`, `to_id`) take the same forms. In Rust a record id is any `IntoRecordId` value: an integer, a `String` or a `&str`; array ids have no Rust counterpart.

**Ownership.** `declare_record` writes with `UPSERT ... MERGE`, never `CONTENT`: fields written by other owners survive, and fields you stop declaring are unset. Use `declare_fields` when a pipeline contributes only some fields of a record that another pipeline owns. Relation records are single-owner and are replaced whole.

**DDL.** Table and field definitions use `OVERWRITE`, so they are idempotent. With `managed_by="user"` CocoIndex never runs DDL on tables (indexes declared with `declare_vector_index` are still created).

`declare_table_target` declares a schemaless, system-managed table. The `mount_*` forms (`mount_table_target`, `mount_table_target_with_schema`, `mount_table_target_with_options`, `mount_table_target_with_schema_and_options`) are `async` and return a resolved target. `ManagedTargetOptions::user_managed()` is Python's `managed_by="user"`.

**Parameters:**

- `db` — A `ContextKey[surrealdb.ConnectionFactory]` for the SurrealDB connection.
- `table_name` — Name of the table.
- `table_schema` — Optional schema definition (see [Table Schema](#table-schema-from-python-class)). When provided, the table is `SCHEMAFULL`; when omitted, the table is `SCHEMALESS`.
- `managed_by` — Whether CocoIndex manages the table lifecycle (`"system"`) or assumes it exists (`"user"`).

**Returns:** A pending `TableTarget`. Use `await surrealdb.mount_table_target(SURREAL_DB, ...)` to get a resolved target.

```rust
pub fn TableTarget::declare_fields<R: serde::Serialize>(
    &self,
```

`fields` is a struct or map that serializes to an object of field name to value; it cannot name `id`. For example:

```rust
// Component A owns the record.
players.declare_record(ctx, "ann", &json!({ "name": "Ann" }))?;
// Component B owns the `stats` fields of the same record.
players.declare_fields(ctx, "ann", "stats", &json!({ "score": 7, "rank": 1 }))?;
```

</Fragment>
</LangTabs>

Declares the fields one owner (`group`) contributes to a record. It runs `UPDATE $id MERGE {fields}` and touches nothing else. When the declaration goes away, or a field is dropped from it, those fields are unset. If the record does not exist, the write raises and is retried on the next run, so declare the base record in the same or another pipeline.

**Parameters:**

- `to_id` — ID of the target record.

#### Vector indexes (attachment)

Declare a vector index on a field of the table. CocoIndex tracks the index spec and automatically creates, recreates, or drops the index as needed.

```python
    method: Literal["hnsw"] = "hnsw",
```

</Fragment>
<Fragment slot="rust">

```rust
    &self,
    ctx: &Ctx,
    field: &str,
    dimension: usize,
    options: VectorIndexOptions,

pub struct VectorIndexOptions {
    /// Index name; defaults to `idx_<table>__<field>`.
    pub name: Option<String>,
    /// Distance metric: `"cosine"`, `"euclidean"`, or `"manhattan"`.
    pub metric: &'static str,
    /// Index method: `"mtree"` or `"hnsw"`.
    pub method: &'static str,
    /// Vector element type: `"f32"`, `"f64"`, `"i16"`, `"i32"`, or `"i64"`.
    pub vector_type: &'static str,

```

For example:

```rust
docs.declare_vector_index(
    &ctx,
    "embedding",
    3,
    VectorIndexOptions {
        metric: "cosine",
        method: "hnsw",
        ..Default::default()
    },
)?;
```

The Rust default `method` is `"mtree"`, which SurrealDB 3 removed: set `method: "hnsw"`.

</Fragment>
</LangTabs>

**Parameters:**

- `name` — Index name (defaults to `idx_{table}__{field}`).
- `field` — Field to index (must be a vector/array field).
- `metric` — Distance metric: `"cosine"`, `"euclidean"`, or `"manhattan"`.
- `method` — Index method: `"hnsw"` (SurrealDB 3 removed `MTREE`).
- `dimension` — Vector dimension (required).
- `vector_type` — Vector element type: `"f32"`, `"f64"`, `"i16"`, `"i32"`, or `"i64"`.

### Table schema: from Python class

Define the table structure using a Python class (dataclass, NamedTuple, or Pydantic model):

{/* Rust: rust/sdk/SHOWCASE.md (SurrealDB), verified against rust/sdk/cocoindex/src/connectors/surrealdb.rs */}
<LangTabs>
<Fragment slot="python">

```python
@classmethod
async def TableSchema.from_class(
    cls,
    record_type: type[RowT],
    *,
    column_overrides: dict[str, SurrealType | VectorSchemaProvider] | None = None,
) -> TableSchema[RowT]
```

</Fragment>
<Fragment slot="rust">

```rust
pub fn TableSchema::from_row<T: SchemaFields>() -> Result<Self>
```

The row type derives `cocoindex::SchemaFields`. The record id is passed to `declare_record` separately, so the struct has no `id` field:

```rust
#[derive(Serialize, SchemaFields)]
struct Session {
    name: String,
    description: Option<String>,        // option<string>
    recorded_at: chrono::DateTime<chrono::Utc>, // datetime
    #[coco(vector = 384)]
    embedding: Vec<f32>,                // array<float, 384>
}

let sessions = surrealdb::mount_table_target_with_schema(
    ctx, &GRAPH, "session", Some(surrealdb::TableSchema::from_row::<Session>()?),
)
.await?;
sessions.declare_record(ctx, session_id, &session)?;
```

A vector field needs `#[coco(vector = N)]` with its dimension; a bare `#[coco(vector)]` is an error for SurrealDB.

</Fragment>
</LangTabs>

**Parameters:**

- `record_type` — A record type whose fields define table columns. For normal tables, must include an `id` field. For relation tables, `id` is optional.
- `column_overrides` — Optional per-column overrides for type mapping or vector configuration. In Rust, a `#[coco(..)]` attribute on the field does this (see below).

**Example:**

```python
@dataclass
class Product:
    id: str
    name: str
    price: float
    embedding: Annotated[NDArray, embedder]

schema = await surrealdb.TableSchema.from_class(Product)
```

Python types are automatically mapped to SurrealDB types:

| Python Type | Rust Type | SurrealDB Type |
|-------------|-----------|----------------|
| `bool` | `bool` | `bool` |
| `int` | `i16`, `i32`, `i64` (and the unsigned widths) | `int` |
| `float` | `f32`, `f64` | `float` |
| `decimal.Decimal` | `rust_decimal::Decimal` | `decimal` |
| `str` | `String` | `string` |
| `bytes` | `Vec<u8>` | `bytes` |
| `uuid.UUID` | `uuid::Uuid` | `uuid` |
| `datetime.datetime` | `chrono::DateTime`, `chrono::NaiveDateTime` | `datetime` |
| `datetime.date` | `chrono::NaiveDate` | `datetime` |
| `datetime.time` | `chrono::NaiveTime` | `datetime` (Python), `string` (Rust) |
| `datetime.timedelta` | `std::time::Duration` | `duration` |
| `list`, `dict`, nested structs | other `Vec<T>`, maps, nested structs, `#[coco(json)]` | `object` (Python), `any` (Rust) |
| `NDArray` (with vector schema) | `#[coco(vector = N)] Vec<f32>` | `array<float, N>` |

```rust
#[derive(Clone, Debug, Serialize, cocoindex::SchemaFields)]
pub struct StatementRow {
    pub statement: String,

/// A person, tech or org node.
#[derive(Clone, Debug, Serialize, cocoindex::SchemaFields)]
pub struct EntityRow {
    pub name: String,

pub async fn create_knowledge_base(ctx: &Ctx, processed: &[ProcessedSession]) -> Result<()> {
    let session_target = surrealdb::mount_table_target_with_schema(
        ctx,
        &GRAPH,
        "session",
        Some(surrealdb::TableSchema::from_row::<SessionRow>()?),
    )
    .await?;
    let statement_target = surrealdb::mount_table_target_with_schema(
        ctx,
        &GRAPH,
        "statement",
        Some(surrealdb::TableSchema::from_row::<StatementRow>()?),
    )
    .await?;
    let person_target = surrealdb::mount_table_target_with_schema(
        ctx,
        &GRAPH,
        "person",
        Some(surrealdb::TableSchema::from_row::<EntityRow>()?),
    )
    .await?;
    let tech_target = surrealdb::mount_table_target_with_schema(
        ctx,
        &GRAPH,
        "tech",
        Some(surrealdb::TableSchema::from_row::<EntityRow>()?),
    )
    .await?;
    // Declare a relation table (schemaless, no id needed)
    let session_statement_target = surrealdb::mount_relation_target(
        ctx,
        &GRAPH,
        "session_statement",
        &session_target,
        &statement_target,
    )
    .await?;
    // A polymorphic relation: a statement mentions a person or a tech.
    let statement_mentions_target = surrealdb::mount_relation_target_many(
        ctx,
        &GRAPH,
        "statement_mentions",
        &[&statement_target],
        &[&person_target, &tech_target],
        None,
    )
    .await?;

    for ps in processed {
        for st in &ps.statements {
            statement_target.declare_record(
                ctx,
                st.id,
                &StatementRow {
                    statement: st.raw.statement.clone(),
                },
            )?;
            // Declare relations — id is auto-derived from endpoints
            session_statement_target.declare_relation(ctx, ps.session_id, st.id)?;
            for name in st.raw.mentioned("person") {
                statement_mentions_target.declare_relation_between(
                    ctx,
                    "statement",
                    st.id,
                    "person",
                    name,
                )?;
            }
        }
    }
    Ok(())
}
```
