The `valkey` connector provides utilities for writing documents to Valkey with vector search support, using the valkey-search module for similarity search indexes.

## Connection setup

`create_client_config()` creates a configuration for connecting to Valkey.

{/* Rust: rust/sdk/cocoindex/src/connectors/valkey.rs */}
<LangTabs>
<Fragment slot="python">

```python
def create_client_config(
    host: str = "localhost",
    port: int = 6379,
    *,
    password: str | None = None,
    use_tls: bool = False,
    client_name: str | None = "cocoindex_vector_store",
    **kwargs: Any,
) -> GlideClientConfiguration
```

</Fragment>
<Fragment slot="rust">

```rust
pub struct ClientConfig {
    pub host: String,                 // default "localhost"
    pub port: u16,                    // default 6379
    pub password: Option<String>,
    pub use_tls: bool,
    pub client_name: Option<String>,  // default Some("cocoindex_vector_store")
}

impl Valkey {
    pub async fn connect(uri: &str) -> Result<Self>
    pub async fn connect_with_config(config: ClientConfig) -> Result<Self>
    pub async fn from_client(state_id: impl Into<String>, client: &redis::Client) -> Result<Self>
}
```

`Valkey::connect_with_config(ClientConfig { .. })` is the counterpart of `create_client_config` plus `GlideClient.create`. `Valkey::connect("redis://localhost:6379")` takes a URI. For anything `ClientConfig` does not cover (`**kwargs` in Python: client certificates, a username, a database number), build a `redis::Client` yourself and pass it to `from_client`.

</Fragment>
</LangTabs>

**Parameters:**

- `host` — Valkey server host (default: `"localhost"`).
- `port` — Valkey server port (default: `6379`).
- `password` — Optional authentication password.
- `use_tls` — Whether to use TLS for the connection (default: `False`).
- `client_name` — Client name for the connection, visible in `CLIENT LIST` and monitoring dashboards (default: `"cocoindex_vector_store"`). Pass `None` to disable.
- `**kwargs` — Additional keyword arguments passed to `GlideClientConfiguration`. `client_info_tag` defaults to `"cocoindex"`, so the server attributes the connection to CocoIndex via `CLIENT SETINFO LIB-NAME` unless you override it.

For advanced configurations not covered by these parameters, construct `GlideClientConfiguration` directly.

**Returns:** A `GlideClientConfiguration` instance.

**Example:**

## As target

The `valkey` connector provides target state APIs for writing documents to search indexes. CocoIndex tracks what documents should exist and automatically handles upserts and deletions.

### Declaring target states

#### Setting up a connection

Create a `ContextKey[GlideClient]` to identify your Valkey client, then provide it in your lifespan:

:::note
The key name is load-bearing across runs — it's the stable identity CocoIndex uses to track managed indexes. See [ContextKey as stable identity](../programming_guide/context#contextkey-as-stable-identity) before renaming.
:::

{/* Rust: rust/sdk/cocoindex/tests/valkey_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from glide import GlideClient
import cocoindex as coco
from cocoindex.connectors import valkey

VALKEY_DB = coco.ContextKey[GlideClient]("my_valkey")

@coco.lifespan
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:
    config = valkey.create_client_config("localhost", 6379)
    client = await GlideClient.create(config)
    builder.provide(VALKEY_DB, client)
    yield
    await client.close()
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::valkey;

cocoindex::context_key!(static VK: valkey::Valkey, key = "valkey_target_conn");

let vk = valkey::Valkey::connect(&uri).await?;
// Provide it on the environment builder, or in a `#[cocoindex::lifespan]`:
let builder = Environment::builder().provide_key(&VK, vk);
```

`context_key!` declares the key. Its stable name is the identifier, or the `key = "…"` string when given. There is no `close()`: drop the `Valkey` handle.

</Fragment>
</LangTabs>

#### Indexes (parent state)

Declares a search index as a target state. Returns an `IndexTarget` for declaring documents.

```python
    index_name: str,
    schema: IndexSchema,
    *,
    managed_by: ManagedBy = ManagedBy.SYSTEM,
) -> IndexTarget[coco.PendingS]
```

</Fragment>
<Fragment slot="rust">

```rust
pub fn declare_index_target(
    ctx: &Ctx,
    db: &ContextKey<Valkey>,
    index_name: impl Into<String>,
    schema: IndexSchema,
) -> Result<IndexTarget>

pub async fn mount_index_target(
    ctx: &Ctx,
    db: &ContextKey<Valkey>,
    index_name: impl Into<String>,
    schema: IndexSchema,
) -> Result<IndexTarget>

pub fn index_target_with_options(
    ctx: &Ctx,
    db: &ContextKey<Valkey>,
    index_name: impl Into<String>,
    schema: IndexSchema,
    options: ManagedTargetOptions,

```

`managed_by` is set with `ManagedTargetOptions::user_managed()` on `index_target_with_options`, which returns the raw `TargetState` for `mount_target` / `declare_target_state_with_child`. `declare_index_target` returns a handle whose documents resolve when the current component commits; `mount_index_target(...).await?` returns a handle that accepts documents at once.

</Fragment>
</LangTabs>

**Parameters:**

- `db` — A `ContextKey[GlideClient]` identifying the Valkey client to use.
- `index_name` — Name of the search index.
- `schema` — Schema definition specifying vector configuration (see [Index Schema](#index-schema)).
- `managed_by` — `ManagedBy.SYSTEM` (default): CocoIndex creates and drops the index automatically. `ManagedBy.USER`: assumes the index already exists and never drops it.

**Returns:** A pending `IndexTarget`. Use the convenience wrapper `await valkey.mount_index_target(VALKEY_DB, index_name, schema)` to resolve.

**Parameters:**

- `document` — A `valkey.Document` containing:
  - `id` — Document ID (string)
  - `vector` — Vector data (list of floats or numpy array)
  - `payload` — Optional metadata dict (values must be str, int, or float). The key `vector` is reserved for the vector field (see [Data storage](#data-storage)), so a payload with that key raises a `ValueError`.

</Fragment>

**Parameters:**

- `vectors` — A `VectorDef` specifying the vector field configuration.
- `fields` — Optional list of `FieldDef` for indexed payload fields (enables search/filtering). A `FieldDef` named `vector` raises a `ValueError`: that name is reserved for the vector field.

#### VectorDef

Specifies vector configuration including dimension, distance metric, and algorithm:

{/* Rust: rust/sdk/cocoindex/src/connectors/valkey.rs */}
<LangTabs>
<Fragment slot="python">

```python
class VectorDef(NamedTuple):
    schema: VectorSchemaProvider | ContextKey[VectorSchemaProvider]
    distance: Literal["cosine", "l2", "ip"] = "cosine"
    algorithm: Literal["hnsw", "flat"] = "hnsw"
```

</Fragment>
<Fragment slot="rust">

```rust
pub struct VectorDef<'a> {
    pub schema: &'a (dyn VectorSchemaProvider + 'a),
    pub distance: Distance,          // Cosine (default), L2, Ip
    pub algorithm: VectorAlgorithm,  // Hnsw (default), Flat
}

impl<'a> VectorDef<'a> {
    pub fn new(schema: &'a (dyn VectorSchemaProvider + 'a)) -> Self
}
```

`VectorDef::new(&embedder)` uses the defaults. `schema` borrows the provider; `IndexSchema::create` resolves the dimension at once.

</Fragment>
</LangTabs>

**Parameters:**

- `schema` — A `VectorSchemaProvider` or `ContextKey` that defines vector dimensions.
- `distance` — Distance metric for similarity search (default: `"cosine"`).
- `algorithm` — Vector index algorithm (default: `"hnsw"`).

#### VectorSchemaProvider

The `schema` field of `VectorDef` accepts a [`VectorSchemaProvider`](../common_resources/vector_schema#vectorschemaprovider), a `ContextKey`, or an explicit `VectorSchema` to specify the vector dimension and dtype. See [Vector Schema](../common_resources/vector_schema#vectorschemaprovider) for details. In Rust, pass `&VectorSchema::f32(n)` or a reference to an embedder; for one held in the context, `ctx.get_key(&EMBEDDER)?`.

### Distance metrics

The `distance` parameter in `VectorDef` specifies the similarity metric:

- `"cosine"` — Cosine similarity (default)
- `"l2"` — Euclidean distance (L2)
- `"ip"` — Inner product (dot product)

In Rust: `Distance::Cosine`, `Distance::L2`, `Distance::Ip`.

### Index algorithms

The `algorithm` parameter specifies the vector indexing strategy:

- `"hnsw"` — Hierarchical Navigable Small World graph (default, best for most use cases)
- `"flat"` — Brute-force flat index (exact results, slower for large datasets)

In Rust: `VectorAlgorithm::Hnsw`, `VectorAlgorithm::Flat`.

### Data storage

Documents are stored as Valkey HASH keys with a prefix pattern:

- Key format: `{index_name}:{document_id}`
- Vector field: stored as binary float32 blob in a `vector` hash field
- Payload fields: stored as individual hash fields (string values)

The search index is created with `FT.CREATE ON HASH PREFIX 1 {index_name}:` to automatically index all documents with the matching prefix.

```python
from glide import GlideClient
import cocoindex as coco
from cocoindex.connectors import valkey
from cocoindex.ops.sentence_transformers import SentenceTransformerEmbedder
from typing import AsyncIterator

VALKEY_DB = coco.ContextKey[GlideClient]("main_vectors")
EMBEDDER = coco.ContextKey[SentenceTransformerEmbedder]("embedder")

@coco.lifespan
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:
    config = valkey.create_client_config("localhost", 6379)
    client = await GlideClient.create(config)
    builder.provide(VALKEY_DB, client)
    builder.provide(EMBEDDER, SentenceTransformerEmbedder("all-MiniLM-L6-v2"))
    yield
    await client.close()

@coco.fn
async def process_document(
    doc_id: str,
    text: str,
    target: valkey.IndexTarget,
) -> None:
    embedder = coco.use_context(EMBEDDER)
    embedding = await embedder.embed(text)

    target.declare_document(valkey.Document(
        id=doc_id,
        vector=embedding.tolist(),
        payload={"text": text},
    ))

@coco.fn
async def app_main() -> None:
    embedder = coco.use_context(EMBEDDER)

    index = await valkey.mount_index_target(
        VALKEY_DB,
        "documents",
        await valkey.IndexSchema.create(
            vectors=valkey.VectorDef(schema=embedder, distance="cosine"),
        ),
    )

    for doc_id, text in documents:
        await coco.mount(
            coco.component_subpath("doc", doc_id),
            process_document,
            doc_id,
            text,
            index,
        )
```

```rust
use std::collections::BTreeMap;

use cocoindex::connectors::valkey::{
    self, Distance, Document, FieldDef, FieldType, IndexSchema, VectorAlgorithm, VectorDef,
};
use cocoindex::prelude::*;

cocoindex::context_key!(static VK: valkey::Valkey, key = "valkey_target_conn");

async fn schema() -> IndexSchema {
    IndexSchema::create(
        VectorDef {
            schema: &VectorSchema::f32(3),
            distance: Distance::Cosine,
            algorithm: VectorAlgorithm::Hnsw,
        },
        vec![FieldDef::new("text", FieldType::Text)],
    )
    .await
    .unwrap()
}

fn doc(id: &str, vector: Vec<f32>, text: &str) -> Document {
    let mut payload = BTreeMap::new();
    payload.insert("text".to_string(), text.to_string());
    Document::new(id, vector).with_payload(payload)
}

// In the app:
let index = valkey::mount_index_target(&ctx, &VK, index_name, schema().await).await?;
index.declare_document(&ctx, doc("d1", vec![0.1, 0.2, 0.3], "hello"))?;
index.declare_document(&ctx, doc("d2", vec![0.4, 0.5, 0.6], "world"))?;
```

## Vector search

The connector focuses on writing documents to Valkey. For vector search queries, use the Valkey GLIDE client directly. The Rust SDK has no search helper for Valkey: run `FT.SEARCH` through the `redis` crate.

```python
from glide import GlideClient
from glide.async_commands import ft
from glide.async_commands.ft import FtSearchOptions
import struct

# Build a KNN query
query_vec = struct.pack(f"<{len(embedding)}f", *embedding)
query = f"*=>[KNN 10 @vector $query_vec AS score]"

results = await ft.search(
    client,
    "documents",
    query,
    options=FtSearchOptions(params={"query_vec": query_vec}),
)
```
