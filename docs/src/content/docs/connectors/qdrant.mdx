The `qdrant` connector provides utilities for writing points to Qdrant vector databases, with support for single vectors, named dense vectors, sparse vectors, and multi-vector configurations.

## Connection setup

```python
    *,
    prefer_grpc: bool = True,
    **kwargs: Any,

```

</Fragment>
<Fragment slot="rust">

```rust
impl QdrantConnection {
    pub async fn connect(url: &str) -> Result<Self>
    pub fn from_client(state_id: impl Into<String>, client: Qdrant) -> Self
    pub fn client(&self) -> &Qdrant
}
```

`QdrantConnection::connect(url)` takes the gRPC URL (for example `http://localhost:6334`) and uses the client's defaults. For an API key, TLS or timeouts, build a `qdrant_client::Qdrant` yourself and wrap it with `from_client`; `state_id` should name the server, not hold a secret.

- `prefer_grpc` — Whether to prefer gRPC over HTTP (default: `True`).
- `**kwargs` — Additional arguments passed directly to `QdrantClient`.

**Returns:** A Qdrant client instance.

## As target

The `qdrant` connector provides target state APIs for writing points to collections. CocoIndex tracks what points should exist and automatically handles upserts and deletions.

### Declaring target states

#### Setting up a connection

Create a `ContextKey[QdrantClient]` to identify your Qdrant client, then provide it in your lifespan:

:::note
The key name is load-bearing across runs — it's the stable identity CocoIndex uses to track managed collections. See [ContextKey as stable identity](../programming_guide/context#contextkey-as-stable-identity) before renaming.
:::

{/* Rust: examples/rust/text_embedding_qdrant/src/main.rs, rust/sdk/cocoindex/tests/qdrant_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
from qdrant_client import QdrantClient
import cocoindex as coco

QDRANT_DB = coco.ContextKey[QdrantClient]("my_vectors")

@coco.lifespan
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:
    client = qdrant.create_client(QDRANT_URL)
    builder.provide(QDRANT_DB, client)
    yield
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::qdrant::QdrantConnection;

cocoindex::context_key!(static DB: QdrantConnection);

let conn = QdrantConnection::connect(&url).await?;

    .db_path(tempdir.path().join(".cocoindex_db"))
    .provide_key(&DB, conn)
    .build()
    .await?
    .app("QdrantTargetTest")
    .await?;
```

`context_key!(static DB: QdrantConnection)` declares the key; its name is the stable identity. `provide_key(&DB, conn)` provides the connection, in a `#[cocoindex::lifespan]` function or on `Environment::builder()` as here.

`managed_by` is set with `ManagedTargetOptions::user_managed()` on the `_with_options` variants. `declare_collection_target` returns a handle whose points resolve when the current component commits; `mount_collection_target(...).await?` returns a handle that accepts points at once.

</Fragment>

**Parameters:**

- `db` — A `ContextKey[QdrantClient]` identifying the Qdrant client to use.
- `collection_name` — Name of the collection.
- `schema` — Schema definition specifying vector configurations (see [Collection Schema](#collection-schema)).
- `managed_by` — Whether CocoIndex manages the collection lifecycle (`"system"`) or assumes it exists (`"user"`).

**Returns:** A pending `CollectionTarget`. Use the convenience wrapper `await qdrant.mount_collection_target(QDRANT_DB, collection_name, schema)` to resolve.

#### Points (child states)

Once a `CollectionTarget` is resolved, declare points to be upserted using `qdrant.PointStruct`, which is an alias of `qdrant_client.http.models.PointStruct`:

{/* Rust: rust/sdk/cocoindex/src/connectors/qdrant.rs */}
<LangTabs>
<Fragment slot="python">

```python
def CollectionTarget.declare_point(
    self,
    point: qdrant.PointStruct,
) -> None
```

</Fragment>
<Fragment slot="rust">

```rust
impl CollectionTarget {
    /// A single-vector point.
    pub fn declare_point(
        &self,
        ctx: &Ctx,
        id: impl Into<QdrantPointId>,
        vector: Vec<f32>,
        payload: Map<String, JsonValue>,
    ) -> Result<()>

    /// A point for a named-vector collection: each value is a single vector,
    /// a multivector or a sparse vector.
    pub fn declare_named_vectors_point<I, K>(
        &self,
        ctx: &Ctx,
        id: impl Into<QdrantPointId>,
        vectors: I,
        payload: Map<String, JsonValue>,
    ) -> Result<()>
    where
        I: IntoIterator<Item = (K, NamedPointVector)>,
        K: Into<String>

    /// A multi-vector point for a collection created with
    /// `CollectionSchema::multivector`.
    pub fn declare_multivector_point(
        &self,
        ctx: &Ctx,
        id: impl Into<QdrantPointId>,
        vectors: Vec<Vec<f32>>,
        payload: Map<String, JsonValue>,
    ) -> Result<()>
}
```

The Rust SDK has no `PointStruct`: the id, the vector and the payload are separate arguments, and the shape of the vector picks the method. The payload is a `serde_json::Map<String, Value>`.

</Fragment>
</LangTabs>

**Parameters:**

- `point` — A `qdrant.PointStruct` (alias of `qdrant_client.http.models.PointStruct`) containing:
  - `id` — Point ID (str, int, or UUID)
  - `vector` — Vector data (single vector or dict of named vectors)
  - `payload` — Optional metadata as a JSON-serializable dict

### Collection schema

Define vector configurations for a collection using `CollectionSchema`. Unlike row-oriented databases, Qdrant uses a point-oriented model where each point has schemaless payload and one or more vectors with predefined dimensions.

{/* Rust: rust/sdk/cocoindex/src/connectors/qdrant.rs */}
<LangTabs>
<Fragment slot="python">

```python
class CollectionSchema:
    @classmethod
    async def create(
        cls,
        vectors: QdrantVectorDef
        | dict[str, QdrantVectorDef | QdrantSparseVectorDef]
        | None = None,
    ) -> CollectionSchema
```

</Fragment>
<Fragment slot="rust">

```rust
impl CollectionSchema {
    // One unnamed dense vector per point
    pub fn new(vector_size: u64, distance: Distance) -> Self
    pub fn from_vector_schema(schema: VectorSchema, distance: Distance) -> Result<Self>
    pub async fn from_vector_provider(
        provider: &(impl VectorSchemaProvider + ?Sized),
        distance: Distance,
    ) -> Result<Self>

    // One unnamed multivector per point
    pub fn multivector(vector_size: u64, distance: Distance) -> Self
    pub fn from_multivector_schema(schema: MultiVectorSchema, distance: Distance) -> Result<Self>
    pub async fn from_multivector_provider(
        provider: &(impl MultiVectorSchemaProvider + ?Sized),
        distance: Distance,
    ) -> Result<Self>

    // Named vectors, dense and sparse
    pub fn named<I, K, V>(vectors: I) -> Result<Self>
    where
        I: IntoIterator<Item = (K, V)>,
        K: Into<String>,
        V: Into<QdrantNamedVectorDef>

    // Named dense vectors from a `#[derive(SchemaFields)]` row
    pub fn from_row<T: SchemaFields>(distance: Distance) -> Result<Self>
    pub fn with_vector_dim(self, field_name: &str, dim: usize) -> Result<Self>
}
```

The Rust schema has one constructor per shape instead of one `create` with a union argument. `from_row` turns each `#[coco(vector)]` field of a row struct into a named dense vector; the other fields stay payload.

</Fragment>
</LangTabs>

**Parameters:**

- `vectors` — Either:
  - A single `QdrantVectorDef` for an unnamed dense vector
  - A dict mapping vector names to `QdrantVectorDef` (dense) or `QdrantSparseVectorDef` (sparse)

Dense and sparse vectors share one namespace in Qdrant (the server rejects duplicate names across the two kinds), so both live in the same dict — a name collision is impossible to express. Sparse vectors are always named.

#### QdrantVectorDef

Specifies vector configuration including dimension, distance metric, and multi-vector settings:

{/* Rust: rust/sdk/cocoindex/src/connectors/qdrant.rs */}
<LangTabs>
<Fragment slot="python">

```python
class QdrantVectorDef(NamedTuple):
    schema: VectorSchemaProvider | MultiVectorSchemaProvider
    distance: Literal["cosine", "dot", "euclid"] = "cosine"
    multivector_comparator: Literal["max_sim"] = "max_sim"
```

</Fragment>
<Fragment slot="rust">

```rust
pub struct QdrantVectorDef {
    pub distance: Distance,
    pub multivector_comparator: MultivectorComparator,
    // the vector schema, set by the constructors
}

impl QdrantVectorDef {
    pub fn new(schema: VectorSchema, distance: Distance) -> Result<Self>
    pub fn f32(size: u64, distance: Distance) -> Result<Self>
    pub async fn from_vector_provider(
        provider: &(impl VectorSchemaProvider + ?Sized),
        distance: Distance,
    ) -> Result<Self>
    pub fn multivector(schema: MultiVectorSchema, distance: Distance) -> Result<Self>
    pub async fn from_multivector_provider(
        provider: &(impl MultiVectorSchemaProvider + ?Sized),
        distance: Distance,
    ) -> Result<Self>
}

pub enum Distance { Cosine, Dot, Euclid }
pub enum MultivectorComparator { MaxSim }
```

</Fragment>
</LangTabs>

**Parameters:**

- `schema` — A `VectorSchemaProvider` or `MultiVectorSchemaProvider` that defines vector dimensions
- `distance` — Distance metric for similarity search (default: `"cosine"`)
- `multivector_comparator` — Comparator for multi-vector fields (only applies to `MultiVectorSchemaProvider`)

#### Dense + sparse vectors

For hybrid retrieval, declare a named dense vector and a named sparse vector in the same collection:

```python
from qdrant_client.http import models as qdrant_models
from cocoindex.resources.schema import VectorSchema
import numpy as np

schema = await qdrant.CollectionSchema.create(
    vectors={
        "dense": qdrant.QdrantVectorDef(
            schema=VectorSchema(dtype=np.dtype(np.float32), size=384),
            distance="cosine",
        ),
        "sparse": qdrant.QdrantSparseVectorDef(modifier="idf"),
    },
)
```

#### VectorSchemaProvider

The `schema` field of `QdrantVectorDef` accepts a [`VectorSchemaProvider`](../common_resources/vector_schema#vectorschemaprovider), a `ContextKey`, or an explicit `VectorSchema` to specify the vector dimension and dtype. See [Vector Schema](../common_resources/vector_schema#vectorschemaprovider) for details.

In Rust, `QdrantVectorDef::new(VectorSchema::f32(384), distance)` takes an explicit schema and `QdrantVectorDef::from_vector_provider(&embedder, distance).await?` takes a provider. An `f16` schema is stored as Qdrant's `Float16` datatype.

### Distance metrics

The `distance` parameter in `QdrantVectorDef` specifies the similarity metric:

- `"cosine"` — Cosine similarity (default, normalized dot product)
- `"dot"` — Dot product similarity
- `"euclid"` — Euclidean distance (L2)

In Rust these are the `Distance::Cosine`, `Distance::Dot` and `Distance::Euclid` variants. Every Rust constructor takes the distance explicitly; there is no default.

### Example: single vector

For Rust, the single-vector shape is `CollectionSchema::new(size, Distance::Cosine)` with `declare_point`, shown under [Single (unnamed) vector](#single-unnamed-vector). The end-to-end Rust example, `examples/rust/text_embedding_qdrant`, uses a named vector derived from a row struct; see [Example: named vectors](#example-named-vectors).

```python
from qdrant_client import QdrantClient
import cocoindex as coco
from cocoindex.connectors import qdrant
from cocoindex.ops.sentence_transformers import SentenceTransformerEmbedder
from typing import AsyncIterator

QDRANT_URL = "http://localhost:6333"
QDRANT_DB = coco.ContextKey[QdrantClient]("main_vectors")

embedder = SentenceTransformerEmbedder("sentence-transformers/all-MiniLM-L6-v2")

@coco.lifespan
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:
    client = qdrant.create_client(QDRANT_URL)
    builder.provide(QDRANT_DB, client)
    yield

@coco.fn
async def process_document(
    doc_id: str,
    text: str,
    target: qdrant.CollectionTarget,
) -> None:
    embedding = await embedder.embed(text)

    point = qdrant.PointStruct(
        id=doc_id,
        vector=embedding.tolist(),
        payload={"text": text},
    )
    target.declare_point(point)

@coco.fn
async def app_main() -> None:
    # Declare collection target state
    collection = await qdrant.mount_collection_target(
        QDRANT_DB,
        "documents",
        await qdrant.CollectionSchema.create(
            vectors=qdrant.QdrantVectorDef(schema=embedder)
        ),
    )

    # Declare points
    for doc_id, text in documents:
        await coco.mount(
            coco.component_subpath("doc", doc_id),
            process_document,
            doc_id,
            text,
            collection,
        )
```

```rust
async fn app_main(ctx: Ctx, sourcedir: PathBuf) -> Result<()> {
    let vector_dim = ctx.get_key(&EMBEDDER)?.dimension();
    let target = qdrant::mount_collection_target(
        &ctx,
        &DB,
        COLLECTION,
        CollectionSchema::from_row::<PointData>(Distance::Cosine)?
            .with_vector_dim("vector", vector_dim)?,
    )
    .await?;

    let files = walk_items(&sourcedir, &["**/*.md"])?;
    let points_by_file = mount_each!(files, |file| process_file(ctx, file)).await?;

    for points in &points_by_file {
        for p in points {
            let payload = json!({
                "filename": p.filename,
                "chunk_start": p.chunk_start,
                "chunk_end": p.chunk_end,
                "text": p.text,
            })
            .as_object()
            .unwrap()
            .clone();
            target.declare_named_vectors_point(
                &ctx,
                p.id,
                [("vector", NamedPointVector::Single(p.vector.clone()))],
                payload,
            )?;
        }
    }
    Ok(())
}
```

## Point IDs

Qdrant only accepts two point ID types — this is enforced by the Qdrant server itself (see [Qdrant's Point IDs documentation](https://qdrant.tech/documentation/manage-data/points/#point-ids)):

- `int` — unsigned 64-bit integers (`0 <= id < 2**64`)
- `str` — UUID strings, in any standard textual form (hyphenated, 32-character hex, or URN)

`uuid.UUID` instances are also accepted and converted to strings. `declare_point` validates the ID eagerly and raises `ValueError` for anything else, rather than letting the write fail later at the Qdrant server.

In Rust, the id argument is `impl Into<QdrantPointId>`: a `u64` becomes `QdrantPointId::Num`, and a `String` or `&str` becomes `QdrantPointId::Uuid`.

Qdrant stores every textual form of one UUID as the same point. CocoIndex therefore tracks a UUID point ID in its canonical form (hyphenated, lower case). If you declare two forms of one UUID in the same run, the second declaration fails as a duplicate.

To derive a stable point ID from an arbitrary string key (e.g. a document path or chunk key), use a deterministic UUID:

```python
import uuid

point_id = str(uuid.uuid5(uuid.NAMESPACE_URL, f"doc/{chunk_key}"))
```

## Payloads

Point payloads are schemaless JSON objects. Any JSON-serializable Python data structure can be used. In Rust, the payload is a `serde_json::Map<String, Value>`, for example `json!({...}).as_object().unwrap().clone()`:

```python
payload = {
    "text": "Document content",
    "metadata": {
        "author": "Alice",
        "tags": ["machine-learning", "nlp"],
        "published": "2024-01-15",
    },
    "stats": {
        "views": 1500,
        "likes": 42,
    },
}
```
