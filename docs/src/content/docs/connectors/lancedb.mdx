The `lancedb` connector provides utilities for writing rows to LanceDB tables, with automatic schema inference from <Lang only="python">Python classes</Lang><Lang only="rust">Rust structs</Lang> and support for declaring vector and full-text search (FTS) indexes. CocoIndex manages the table lifecycle (creating, dropping, and evolving the schema) and keeps rows in sync via incremental upserts and deletions.

The `lancedb` connector provides target state APIs for writing rows to tables. CocoIndex tracks what rows should exist and automatically handles upserts and deletions.

**Parameters:**

<Lang only="python">

- `db` — A `ContextKey[LanceAsyncConnection]` identifying the connection to use.
- `table_name` — Name of the table.
- `table_schema` — Schema definition including columns and primary key (see [Table Schema](#table-schema-from-python-class)).

**Returns:** A pending `TableTarget`. Resolve it with `await target`.

For the common case where you want a ready-to-use target immediately, use `mount_table_target()`:

```python
async def mount_table_target(
    db: ContextKey[LanceAsyncConnection],
    table_name: str,
    table_schema: TableSchema[RowT],
    *,
    managed_by: ManagedBy = ManagedBy.SYSTEM,
) -> TableTarget[RowT]
```

For lower-level composition with `coco.mount_target()`, `table_target()` returns the raw target
state:

```python
def table_target(
    db: ContextKey[LanceAsyncConnection],
    table_name: str,
    table_schema: TableSchema[RowT],
    *,
    managed_by: ManagedBy = ManagedBy.SYSTEM,
) -> coco.TargetState
```

</Lang>

<Lang only="rust">

- `ctx` — The component's `Ctx`.
- `db` — The `ContextKey<LanceDatabase>` identifying the connection to use.
- `table_name` — Name of the table. It must start with an ASCII letter or `_` and contain only ASCII letters, digits and `_`.
- `table_schema` — Schema definition including columns and primary key (see [Table Schema](#table-schema-from-a-rust-struct)).
- `options` — `_with_options` variants only. `ManagedTargetOptions::default()` lets CocoIndex manage the table lifecycle; `ManagedTargetOptions::user_managed()` assumes the table exists and never creates or drops it.

**Returns:** `mount_table_target` and `declare_table_target` return a `LanceTableTarget`, ready for declaring rows. `mount_table_target` is the usual choice; `declare_table_target` is a sync form for declaring the table and its rows in the same component. `table_target` returns the raw `TargetState` for `mount_target` / `declare_target_state_with_child`.

A `LanceTableTarget` is `Clone` and `Serialize`. It can be an argument of `mount!`, `use_mount!`, `mount_each!` or a memoized function: it fingerprints by its stable key, the context key name and the table name. The schema and `managed_by` are not part of that identity.

{/* Rust: rust/sdk/cocoindex/tests/lancedb_target.rs (lancedb_table_target_is_a_mount_argument_keyed_by_its_table) */}

```rust
#[cocoindex::function]
async fn declare_row_in_component(
    ctx: &Ctx,
    id: i64,
    table: lancedb::LanceTableTarget,
) -> Result<()> {
    table.declare_row(
        ctx,
        &Row {
            id,
            text: format!("doc{id}"),
            embedding: vec![1.0, 0.0, 0.0],
        },
    )
}

let table = lancedb::mount_table_target(&ctx, &DB, table_name, schema()).await?;
cocoindex::use_mount_each!(vec![("1".to_string(), 1_i64)], |id| {
    declare_row_in_component(ctx, id, table.clone())
})
.await?;
```

</Lang>

<Lang only="python">

CocoIndex automatically runs LanceDB `table.optimize()` when durable table and index statistics
cross internal maintenance thresholds, such as small fragments, deletion files, or unindexed
index tails. This is stats-driven rather than transaction-count-driven, so it works across
many short incremental runs as well as long-running updates.

</Lang>

<Lang only="rust">

CocoIndex automatically runs LanceDB `table.optimize()` once every 50 applied row batches of a table
target in a run. All row batches of a run write through one table handle, opened by the first batch
and moved to the table's latest version before each later one.

</Lang>

<RustNote>
Optimization is counted in row batches, not driven by table and index statistics as in Python. A run with fewer than 50 row batches does not optimize the table.
</RustNote>

Table optimization compacts small fragments, cleans up deletion files, and reindexes new data so
the freshest rows are available through declared indexes; see LanceDB's
[compaction and cleanup](https://docs.lancedb.com/performance#compaction-and-cleanup) guidance.

:::note
Automatic optimize runs inline with CocoIndex's row-mutation path. To avoid LanceDB optimistic
commit conflicts, use CocoIndex as the owner of writes that sync source data into the table.
External LanceDB connections outside CocoIndex should generally be read-only while CocoIndex is
updating the table.
:::

**Parameters:**

- `name` — Logical index name (defaults to <Lang only="python">`column`</Lang><Lang only="rust">`<column>_idx`</Lang>).

- `metric` — Distance metric: `"cosine"` (default), `"l2"`, or `"dot"`.

- `m` — *(HNSW-PQ only)* Maximum number of HNSW edges per node.
- `ef_construction` — *(HNSW-PQ only)* Size of the HNSW candidate list during build.

<Fragment slot="rust">

```rust
impl TableSchema {
    pub fn from_row<T: SchemaFields>(
        primary_key: impl IntoIterator<Item = impl Into<String>>,
    ) -> Result<Self>

    pub fn with_vector_dim(self, field_name: &str, dim: usize) -> Result<Self>
    pub async fn with_vector_schema(
        self,
        field_name: &str,
        provider: &(impl VectorSchemaProvider + ?Sized),
    ) -> Result<Self>
    pub fn with_column_type(self, field_name: &str, col_type: ColumnType) -> Result<Self>
}
```

Per-column overrides are builder calls on the derived schema: `with_vector_schema` or `with_vector_dim` for a vector column, `with_column_type` for a type override. `with_column_type` keeps the column's nullability. Each returns an error for a column that is not in the schema.

</Fragment>
</LangTabs>

**Parameters:**

<Lang only="python">

- `record_type` — A record type whose fields define table columns.
- `primary_key` — List of column names forming the primary key. A primary key column must have a string, binary, boolean, integer, `float32`, `float64` or decimal PyArrow type, and its name can't contain a backtick (`` ` ``). `TableSchema` raises a `ValueError` for any other primary key column.
- `column_specs` — Optional per-column overrides for type mapping or vector configuration.

</Lang>

<Lang only="rust">

- `T` — The row struct whose fields define table columns.
- `primary_key` — Column names forming the primary key. A primary key value must serialize to a string or an integer.

Every column name must start with an ASCII letter or `_` and contain only ASCII letters, digits and `_`.

</Lang>

<Lang only="python">

Python types are automatically mapped to PyArrow types:

| Python Type | PyArrow Type |
|-------------|--------------|
| `bool` | `bool` |
| `int` | `int64` |
| `float` | `float64` |
| `str` | `string` |
| `bytes` | `binary` |
| `list`, `dict`, nested structs | `string` (JSON encoded) |
| `NDArray` (with vector schema) | `fixed_size_list<float>` |

To override the default mapping, provide a `LanceType` or `VectorSchemaProvider` via:

- **Type annotation** — using `typing.Annotated` on the field
- **`column_specs`** — passing overrides when constructing `TableSchema`

</Lang>

<Lang only="rust">

Rust field types are automatically mapped to Arrow types:

| Rust Type | `ColumnType` | Arrow Type |
|-----------|--------------|------------|
| `bool` | `Bool` | `bool` |
| `i16`, `i32`, `i64` | `Int16`, `Int32`, `Int64` | `int16`, `int32`, `int64` |
| `f32`, `f64` | `Float32`, `Float64` | `float32`, `float64` |
| `String`, `Uuid`, dates and times | `Text` | `string` |
| `Vec<u8>` | `Binary` | `binary` |
| other `Vec<T>`, maps, nested structs, `Decimal`, `Duration`, `#[coco(json)]` | `Json` | `string` (JSON encoded) |
| `Vec<f32>` with `#[coco(vector)]` | `Vector(dim)` | `fixed_size_list<float32>` |
| `Vec<f32>` with `#[coco(vector, half)]` | `HalfVector(dim)` | `fixed_size_list<float16>` |

`ColumnType` also has `Int8`, `UInt8`, `UInt16`, `UInt32`, `UInt64` and `Float16`, for `with_column_type` and explicit columns. A `#[coco(type = "…")]` attribute is an error for LanceDB: use `with_column_type` with a `ColumnType`.

</Lang>

```rust
    .with_column_type("value", ColumnType::Float32)?;
```

Or declare the field as `i32` / `f32` in the struct.

</Fragment>
</LangTabs>

<RustNote>
There is no per-column encoder. A Rust row is encoded by its `Serialize` impl: to convert a value before it is written, put `#[serde(serialize_with = "…")]` on the field.
</RustNote>

#### VectorSchemaProvider

<Lang only="python">

For `NDArray` fields, a `VectorSchemaProvider` annotation specifies the vector dimension and dtype. The annotation accepts a `VectorSchemaProvider`, a `ContextKey`, or an explicit `VectorSchema`. See [Vector Schema](../common_resources/vector_schema#vectorschemaprovider) for details.

</Lang>

<Lang only="rust">

For a `#[coco(vector)]` field, `with_vector_schema` takes the vector dimension and element type from a `VectorSchemaProvider`: an embedder, or a `VectorSchema`. For an embedder held in the context, pass `ctx.get_key(&EMBEDDER)?`. An `f16` provider selects a `float16` list; `f32` and `f64` select `float32`. See [Vector Schema](../common_resources/vector_schema#vectorschemaprovider) for details.

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs (with_vector_schema doc comment) */}

```rust
let schema = TableSchema::from_row::<DocEmbedding>(["id"])?
    .with_vector_schema("embedding", ctx.get_key(&EMBEDDER)?)
    .await?;
```

</Lang>

### Table schema: explicit column definitions

Define columns directly using `ColumnDef`:

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs (TableSchema::new, ColumnDef) */}
<LangTabs>
<Fragment slot="python">

```python
def TableSchema.__init__(
    self,
    columns: dict[str, ColumnDef],
    primary_key: list[str],
    *,
    row_type: type[RowT] | None = None,
) -> None
```

`ColumnDef` has the following fields:

```python
class ColumnDef(NamedTuple):
    type: pa.DataType
    nullable: bool = True
    encoder: Callable[[Any], Any] | None = None
```

- `type` — PyArrow type stored in LanceDB.
- `nullable` — Whether the column may contain null values.
- `encoder` — Optional function to convert values before writing them.

</Fragment>
<Fragment slot="rust">

```rust
impl TableSchema {
    pub fn new(
        columns: impl IntoIterator<Item = (impl Into<String>, ColumnDef)>,
        primary_key: impl IntoIterator<Item = impl Into<String>>,
    ) -> Result<Self>
}

impl ColumnDef {
    pub fn new(col_type: ColumnType) -> Self
    pub fn nullable(self) -> Self
}
```

`ColumnDef::new(col_type)` is not nullable; `.nullable()` opts in. `TableSchema::new` returns an error for an empty primary key, a primary key column that is not in `columns`, or a duplicate column.

</Fragment>
</LangTabs>

```python
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:

    # Declare table target state

            primary_key=["doc_id"],
```

```rust
use std::path::PathBuf;

use cocoindex::connectors::lancedb::{self, LanceDatabase, TableSchema};
use cocoindex::prelude::*;

const EMBED_DIM: usize = 384;
const TABLE: &str = "doc_embeddings";

cocoindex::context_key!(static DB: LanceDatabase);

#[derive(Clone, Serialize, Deserialize, SchemaFields)]
struct DocEmbedding {
    id: i64,
    filename: String,
    chunk_start: i64,
    chunk_end: i64,
    text: String,
    #[coco(vector)]
    embedding: Vec<f32>,
}

#[cocoindex::function]
async fn process_file(ctx: &Ctx, file: FileEntry) -> Result<Vec<DocEmbedding>> {
    // chunk and embed the file ...
}

fn doc_embedding_schema() -> Result<TableSchema> {
    TableSchema::from_row::<DocEmbedding>(["id"])?.with_vector_dim("embedding", EMBED_DIM)
}

async fn app_main(ctx: Ctx, sourcedir: PathBuf) -> Result<()> {
    let table = lancedb::mount_table_target(&ctx, &DB, TABLE, doc_embedding_schema()?).await?;

    let files = walk_items(&sourcedir, &["**/*.md"])?;
    let rows_by_file = use_mount_each!(files, |file| process_file(ctx, file)).await?;

    for rows in &rows_by_file {
        for row in rows {
            table.declare_row(&ctx, row)?;
        }
    }
    Ok(())
}
```
