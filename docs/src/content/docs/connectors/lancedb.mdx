The `lancedb` connector provides utilities for writing rows to LanceDB tables, with automatic schema inference from Python classes and support for declaring vector and full-text search (FTS) indexes. CocoIndex manages the table lifecycle (creating, dropping, and evolving the schema) and keeps rows in sync via incremental upserts and deletions.

## Connection setup

LanceDB connections are created directly via the LanceDB library. CocoIndex exposes thin wrappers:

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs */}
<LangTabs>
<Fragment slot="python">

```python
async def connect_async(uri: str, **options: Any) -> LanceAsyncConnection
def connect(uri: str, **options: Any) -> lancedb.DBConnection
```

</Fragment>
<Fragment slot="rust">

```rust
impl LanceDatabase {
    pub async fn connect(uri: &str) -> Result<Self>
    pub fn connection(&self) -> &lancedb::Connection
}
```

`LanceDatabase::connect(uri)` opens (or creates) the database through the [`lancedb`](https://docs.rs/lancedb) crate; `connection()` returns the underlying `lancedb::Connection` for queries. The Rust SDK takes no `**options`.

</Fragment>
</LangTabs>

**Parameters:**

- `uri` — LanceDB URI (local path like `"./lancedb_data"` or cloud URI like `"s3://bucket/path"`).
- `**options` — Additional options passed directly to `lancedb.connect_async()` / `lancedb.connect()`.

**Returns:** A LanceDB connection.

## As target

The `lancedb` connector provides target state APIs for writing rows to tables. CocoIndex tracks what rows should exist and automatically handles upserts and deletions.

### Declaring target states

#### Setting up a connection

Create a `ContextKey[lancedb.LanceAsyncConnection]` to identify your LanceDB connection, then provide it in your lifespan:

:::note
The key name is load-bearing across runs — it's the stable identity CocoIndex uses to track managed tables. See [ContextKey as stable identity](../programming_guide/context#contextkey-as-stable-identity) before renaming.
:::

{/* Rust: examples/rust/code_embedding_lancedb/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
import cocoindex as coco

LANCE_DB = coco.ContextKey[lancedb.LanceAsyncConnection]("main_db")

@coco.lifespan
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:
    conn = await lancedb.connect_async(LANCEDB_URI)
    builder.provide(LANCE_DB, conn)
    yield
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::lancedb::LanceDatabase;

cocoindex::context_key!(static DB: LanceDatabase);

let db = LanceDatabase::connect(&lancedb_uri()).await?;
let app = Environment::builder()
    .db_path(PathBuf::from(env!("CARGO_MANIFEST_DIR")).join(".cocoindex_db"))
    .provide_key(&DB, db)
    .build()
    .await?
    .app("CodeEmbeddingLanceDBRust")
    .await?;
```

`context_key!(static DB: LanceDatabase)` declares the key; its name is the stable identity. `provide_key(&DB, db)` provides the connection, in a `#[cocoindex::lifespan]` function or on `Environment::builder()` as here.

</LangTabs>

#### Tables (parent state)

Declares a table as a target state. Returns a pending `TableTarget` for declaring rows.

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs */}
<LangTabs>
<Fragment slot="python">

```python
def declare_table_target(
    db: ContextKey[LanceAsyncConnection],
    table_name: str,
    table_schema: TableSchema[RowT],
    *,
    managed_by: ManagedBy = ManagedBy.SYSTEM,
) -> TableTarget[RowT, coco.PendingS]
```

</Fragment>
<Fragment slot="rust">

```rust
pub async fn mount_table_target(
    ctx: &Ctx,
    db: &ContextKey<LanceDatabase>,
    table_name: impl Into<String>,
    table_schema: TableSchema,
) -> Result<LanceTableTarget>

pub async fn mount_table_target_with_options(
    ctx: &Ctx,
    db: &ContextKey<LanceDatabase>,
    table_name: impl Into<String>,
    table_schema: TableSchema,
    options: ManagedTargetOptions,
) -> Result<LanceTableTarget>

pub fn table_target(
    ctx: &Ctx,
    db: &ContextKey<LanceDatabase>,
    table_name: impl Into<String>,
    table_schema: TableSchema,
) -> Result<TargetState<TableSpec>>
```

The handle type is `LanceTableTarget`. `managed_by` is set with `ManagedTargetOptions::user_managed()` on the `_with_options` variants (`table_target_with_options`, `mount_table_target_with_options`). `declare_table_target` has the same arguments as `mount_table_target`, and `table_target` returns the raw `TargetState` for `mount_target` / `declare_target_state_with_child`.

</Fragment>
</LangTabs>

**Parameters:**

- `db` — A `ContextKey[LanceAsyncConnection]` identifying the connection to use.
- `table_name` — Name of the table.
- `table_schema` — Schema definition including columns and primary key (see [Table Schema](#table-schema-from-python-class)).
- `managed_by` — Whether CocoIndex manages the table lifecycle (`"system"`) or assumes it exists (`"user"`).
  `ManagedBy` is exported from `cocoindex.connectorkits.target`.

**Returns:** A pending `TableTarget`. Resolve it with `await target`.

For the common case where you want a ready-to-use target immediately, use `mount_table_target()`:

```python
async def mount_table_target(
    db: ContextKey[LanceAsyncConnection],
    table_name: str,
    table_schema: TableSchema[RowT],
    *,
    managed_by: ManagedBy = ManagedBy.SYSTEM,
) -> TableTarget[RowT]
```

For lower-level composition with `coco.mount_target()`, `table_target()` returns the raw target
state:

```python
def table_target(
    db: ContextKey[LanceAsyncConnection],
    table_name: str,
    table_schema: TableSchema[RowT],
    *,
    managed_by: ManagedBy = ManagedBy.SYSTEM,
) -> coco.TargetState
```

CocoIndex automatically runs LanceDB `table.optimize()` when durable table and index statistics
cross internal maintenance thresholds, such as small fragments, deletion files, or unindexed
index tails. This is stats-driven rather than transaction-count-driven, so it works across
many short incremental runs as well as long-running updates.

Table optimization compacts small fragments, cleans up deletion files, and reindexes new data so
the freshest rows are available through declared indexes; see LanceDB's
[compaction and cleanup](https://docs.lancedb.com/performance#compaction-and-cleanup) guidance.

:::note
Automatic optimize runs inline with CocoIndex's row-mutation path. To avoid LanceDB optimistic
commit conflicts, use CocoIndex as the owner of writes that sync source data into the table.
External LanceDB connections outside CocoIndex should generally be read-only while CocoIndex is
updating the table.
:::

#### Vector indexes (attachment)

Declare a vector index on a vector column to accelerate similarity search. Vector indexes are an [attachment](../advanced_topics/custom_target_connector#implementing-attachment-providers) to a `TableTarget`:

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs */}
<LangTabs>
<Fragment slot="python">

```python
def TableTarget.declare_vector_index(
    self,
    *,
    name: str | None = None,
    column: str,
    metric: Literal["cosine", "l2", "dot"] = "cosine",
    index_type: Literal["ivf_pq", "hnsw_pq"] = "ivf_pq",
    num_partitions: int | None = None,
    num_sub_vectors: int | None = None,
    num_bits: int | None = None,
    m: int | None = None,
    ef_construction: int | None = None,
) -> None
```

</Fragment>
<Fragment slot="rust">

```rust
impl LanceTableTarget {
    pub fn declare_vector_index(
        &self,
        ctx: &Ctx,
        column: &str,
        options: VectorIndexOptions,
    ) -> Result<()>
}

pub struct VectorIndexOptions {
    /// Index name; defaults to `<column>_idx`.
    pub name: Option<String>,
    /// Distance metric: "cosine" (default), "l2", or "dot".
    pub metric: &'static str,
    /// Index type: "ivf_pq" (default) or "ivf_hnsw_pq".
    pub index_type: &'static str,
    pub num_partitions: Option<u32>,
    pub num_sub_vectors: Option<u32>,
    pub num_bits: Option<u32>,
    pub m: Option<u32>,
    pub ef_construction: Option<u32>,
}
```

Two names differ from Python: the HNSW index type is `"ivf_hnsw_pq"`, and the default index name is `<column>_idx`, not `column`.

</Fragment>
</LangTabs>

**Parameters:**

- `name` — Logical index name (defaults to `column`).
- `column` — Vector column to index.
- `metric` — Distance metric: `"cosine"` (default), `"l2"`, or `"dot"`.
- `index_type` — Index algorithm: `"ivf_pq"` (IVF-PQ, default) or `"hnsw_pq"` (HNSW-PQ).
- `num_partitions` — *(IVF-PQ only)* Number of IVF partitions.
- `num_sub_vectors` — *(IVF-PQ / HNSW-PQ)* Number of PQ sub-vectors.
- `num_bits` — *(IVF-PQ / HNSW-PQ)* Number of bits per PQ code.
- `m` — *(HNSW-PQ only)* Maximum number of HNSW edges per node.
- `ef_construction` — *(HNSW-PQ only)* Size of the HNSW candidate list during build.

Parameters left as `None` fall back to LanceDB's defaults.

**Example:**

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs (VectorIndexOptions), tests/lancedb_target.rs (declare_fts_index shape) */}
<LangTabs>
<Fragment slot="python">

```python
table.declare_vector_index(column="embedding", metric="cosine")
```

</Fragment>
<Fragment slot="rust">


#### FTS indexes (attachment)

```python
    name: str | None = None,
    column: str,
    language: str = "English",
    with_position: bool = True,
) -> None
```

</Fragment>
<Fragment slot="rust">

```rust
        &self,
        ctx: &Ctx,

pub struct FtsIndexOptions {
    /// Index name; defaults to `<column>_fts_idx`.
    pub name: Option<String>,

    /// Stemming/stop-word language. `None` uses LanceDB's default (English).

}
```

Two defaults differ from Python: `with_position` is `false`, and the index name is `<column>_fts_idx`.

</Fragment>
</LangTabs>

**Parameters:**

- `name` — Logical index name (defaults to `column`).
- `column` — Text column to index.
- `language` — Tokenizer language (e.g. `"English"`, `"Chinese"`).
- `with_position` — Whether to store token positions (enables phrase queries). Defaults to `True`.

**Example:**


:::note
Indexes are reconciled as part of the table's target state: changing a declaration replaces the index in place, removing a declaration drops the index, and dropping the table removes all its indexes.
:::

### Table schema: from Python class

Define the table structure using a Python class (dataclass, NamedTuple, or Pydantic model):

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs */}
<LangTabs>
<Fragment slot="python">

```python
@classmethod
async def TableSchema.from_class(
    cls,
    record_type: type[RowT],
    primary_key: list[str],
    *,
    column_specs: dict[str, LanceType | VectorSchemaProvider] | None = None,
) -> TableSchema[RowT]
```

</Fragment>
<Fragment slot="rust">

```rust
impl TableSchema {
    pub fn from_row<T: SchemaFields>(
        primary_key: impl IntoIterator<Item = impl Into<String>>,
    ) -> Result<Self>

    pub fn with_vector_dim(self, field_name: &str, dim: usize) -> Result<Self>
    pub async fn with_vector_schema(
        self,
        field_name: &str,
        provider: &(impl VectorSchemaProvider + ?Sized),
    ) -> Result<Self>
    pub fn with_column_type(self, field_name: &str, col_type: ColumnType) -> Result<Self>
}
```

The Rust row type is a struct that derives `SchemaFields` (and `Serialize`). Python's `column_specs` become builder calls on the derived schema: `with_vector_schema` or `with_vector_dim` for a vector column, `with_column_type` for a type override.

</Fragment>
</LangTabs>

**Parameters:**

- `record_type` — A record type whose fields define table columns.
- `primary_key` — List of column names forming the primary key. A primary key column must have a string, binary, boolean, integer, `float32`, `float64` or decimal PyArrow type, and its name can't contain a backtick (`` ` ``). `TableSchema` raises a `ValueError` for any other primary key column.
- `column_specs` — Optional per-column overrides for type mapping or vector configuration.

**Example:**

{/* Rust: examples/rust/text_embedding_lancedb/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
@dataclass
class OutputDocument:
    doc_id: str
    title: str
    content: str
    embedding: Annotated[NDArray, embedder]

schema = await lancedb.TableSchema.from_class(
    OutputDocument,
    primary_key=["doc_id"],
)
```

</Fragment>
<Fragment slot="rust">

```rust
#[derive(Clone, Serialize, Deserialize, SchemaFields)]
struct DocEmbedding {
    id: i64,
    filename: String,
    chunk_start: i64,
    chunk_end: i64,
    text: String,
    #[coco(vector)]
    embedding: Vec<f32>,
}

fn doc_embedding_schema() -> Result<TableSchema> {
    TableSchema::from_row::<DocEmbedding>(["id"])?.with_vector_dim("embedding", EMBED_DIM)
}
```

`#[coco(vector)]` marks a vector column whose dimension is set with `with_vector_dim` or `with_vector_schema`; `#[coco(vector = 384)]` fixes it in the struct. `Option<T>` fields become nullable columns.

</Fragment>
</LangTabs>

Python types are automatically mapped to PyArrow types:

| Python Type | Rust Type | PyArrow Type |
|-------------|-----------|--------------|
| `bool` | `bool` | `bool` |
| `int` | `i64` (`i16`: `int16`, `i32`: `int32`) | `int64` |
| `float` | `f64` (`f32`: `float32`) | `float64` |
| `str` | `String`, `Uuid`, dates and times | `string` |
| `bytes` | `Vec<u8>` | `binary` |
| `list`, `dict`, nested structs | other `Vec<T>`, maps, nested structs, `Decimal`, `Duration`, `#[coco(json)]` | `string` (JSON encoded) |
| `NDArray` (with vector schema) | `Vec<f32>` with `#[coco(vector)]` (`half` for `float16`) | `fixed_size_list<float>` |

The Rust `ColumnType` enum names these: `Bool`, `Int16`, `Int32`, `Int64`, `Float32`, `Float64`, `Text`, `Binary`, `Json`, `Vector(dim)` and `HalfVector(dim)`. A `#[coco(type = "…")]` attribute is an error for LanceDB: use `with_column_type` with a `ColumnType`.

To override the default mapping, provide a `LanceType` or `VectorSchemaProvider` via:

- **Type annotation** — using `typing.Annotated` on the field
- **`column_specs`** — passing overrides when constructing `TableSchema`

#### LanceType

Use `LanceType` to specify a custom PyArrow type or encoder:

{/* Rust: rust/sdk/cocoindex/src/connectors/lancedb.rs (with_column_type) */}
<LangTabs>
<Fragment slot="python">

```python
from typing import Annotated
from cocoindex.connectors.lancedb import LanceType
import pyarrow as pa

@dataclass
class MyRow:
    id: Annotated[int, LanceType(pa.int32())]
    value: Annotated[float, LanceType(pa.float32())]
```

`LanceType` also accepts an optional encoder for values that need conversion before writing:

```python
LanceType(pa.string(), encoder=lambda value: json.dumps(value))
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::lancedb::{ColumnType, TableSchema};

let schema = TableSchema::from_row::<MyRow>(["id"])?
    .with_column_type("id", ColumnType::Int32)?
    .with_column_type("value", ColumnType::Float32)?;
```

Or declare the field as `i32` / `f32` in the struct. Python's encoder has no counterpart: a Rust row is encoded by its `Serialize` impl, so put `#[serde(serialize_with = "…")]` on the field.

</Fragment>
</LangTabs>

#### VectorSchemaProvider

For `NDArray` fields, a `VectorSchemaProvider` annotation specifies the vector dimension and dtype. The annotation accepts a `VectorSchemaProvider`, a `ContextKey`, or an explicit `VectorSchema`. See [Vector Schema](../common_resources/vector_schema#vectorschemaprovider) for details.

In Rust, call `with_vector_schema("embedding", ctx.get_key(&EMBEDDER)?).await?` on the derived schema. It takes any `VectorSchemaProvider`: an embedder, or a `VectorSchema`. An `f16` provider selects a `float16` list.

### Table schema: explicit column definitions

Define columns directly using `ColumnDef`:

```python
def TableSchema.__init__(
    self,
    columns: dict[str, ColumnDef],
    primary_key: list[str],
    *,
    row_type: type[RowT] | None = None,
) -> None
```

`ColumnDef` has the following fields:

```python
class ColumnDef(NamedTuple):
    type: pa.DataType
    nullable: bool = True
    encoder: Callable[[Any], Any] | None = None
```

- `type` — PyArrow type stored in LanceDB.
- `nullable` — Whether the column may contain null values.
- `encoder` — Optional function to convert values before writing them.

**Example:**

{/* Rust: rust/sdk/cocoindex/tests/lancedb_target.rs */}
<LangTabs>
<Fragment slot="python">

```python
schema = lancedb.TableSchema(
    {
        "doc_id": lancedb.ColumnDef(type=pa.string(), nullable=False),
        "title": lancedb.ColumnDef(type=pa.string()),
        "content": lancedb.ColumnDef(type=pa.string()),
        "embedding": lancedb.ColumnDef(type=pa.list_(pa.float32(), list_size=384)),
    },
    primary_key=["doc_id"],
)
```

</Fragment>
<Fragment slot="rust">

```rust
use cocoindex::connectors::lancedb::{ColumnDef, ColumnType, TableSchema};

TableSchema::new(
```

### Example

{/* Rust: examples/rust/text_embedding_lancedb/src/main.rs */}
<LangTabs>
<Fragment slot="python">

```python
import cocoindex as coco
from cocoindex.connectors import lancedb

LANCEDB_URI = "./lancedb_data"

LANCE_DB = coco.ContextKey[lancedb.LanceAsyncConnection]("main_db")

@dataclass
class OutputDocument:
    doc_id: str
    title: str
    content: str
    embedding: Annotated[NDArray, embedder]

@coco.lifespan
async def coco_lifespan(builder: coco.EnvironmentBuilder) -> AsyncIterator[None]:
    conn = await lancedb.connect_async(LANCEDB_URI)
    builder.provide(LANCE_DB, conn)
    yield

@coco.fn
async def app_main() -> None:
    # Declare table target state
    table = await lancedb.mount_table_target(
        LANCE_DB,
        "documents",
        await lancedb.TableSchema.from_class(
            OutputDocument,
            primary_key=["doc_id"],
        ),
    )

    # Declare a vector index for similarity search
    table.declare_vector_index(column="embedding", metric="cosine")

    # Declare rows
    for doc in documents:
        table.declare_row(row=doc)
```

</Fragment>
<Fragment slot="rust">

```rust
use std::path::PathBuf;

use cocoindex::connectors::lancedb::{self, LanceDatabase, TableSchema};
use cocoindex::prelude::*;

const EMBED_DIM: usize = 384;
const TABLE: &str = "doc_embeddings";

cocoindex::context_key!(static DB: LanceDatabase);

#[derive(Clone, Serialize, Deserialize, SchemaFields)]
struct DocEmbedding {
    id: i64,
    filename: String,
    chunk_start: i64,
    chunk_end: i64,
    text: String,
    #[coco(vector)]
    embedding: Vec<f32>,
}

#[cocoindex::function]
async fn process_file(ctx: &Ctx, file: FileEntry) -> Result<Vec<DocEmbedding>> {
    // chunk and embed the file ...
}

fn doc_embedding_schema() -> Result<TableSchema> {
    TableSchema::from_row::<DocEmbedding>(["id"])?.with_vector_dim("embedding", EMBED_DIM)
}

async fn app_main(ctx: Ctx, sourcedir: PathBuf) -> Result<()> {
    let table = lancedb::mount_table_target(&ctx, &DB, TABLE, doc_embedding_schema()?).await?;

    let files = walk_items(&sourcedir, &["**/*.md"])?;
    let rows_by_file = mount_each!(files, |file| process_file(ctx, file)).await?;

    for rows in &rows_by_file {
        for row in rows {
            table.declare_row(&ctx, row)?;
        }
    }
    Ok(())
}
```

See `examples/rust/text_embedding_lancedb` for the full program, including the `lancedb::vector_search` query.
