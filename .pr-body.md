Part of splitting #2823 (the Rust SDK battle-test fixes) into reviewable pull requests: the vector targets (Qdrant, Turbopuffer, LanceDB, zvec, Valkey).

## What changes

- **Write batches sized by an estimate.** Qdrant and Turbopuffer sent each batch as one request, however large, and Qdrant's REST limit (`max_request_size_mb`, 32 MiB by default) failed the whole batch. The #2823 review asked that the split not serialize every point a second time to measure it. The new `connectorkits/_request_size.py` estimates an item from its vector lengths (25 bytes per number, an upper bound) plus the JSON of the rest, and `split_by_size` cuts the batch into requests under 16 MiB (Qdrant) or 32 MiB (Turbopuffer); an item larger than that goes alone. Tests assert the split and that vectors are never encoded for sizing.
- **Declare-time checks.** What the server would refuse, or store but never find, now fails where the point is declared, with the point id in the message, instead of failing the whole batch at write time: Qdrant checks a point's vectors against the collection schema (length, empty multivector, NaN/Inf, sparse index repeats and value-count mismatches, undeclared names, unnamed vector in a named collection); Valkey checks a document's vector as the float32 the index stores (dimension, finiteness, float32 range); zvec checks a document id (empty, over 1024 bytes, control character); LanceDB validates the table name when the table target is declared.
- **Vector dtypes.** Qdrant creates the collection with the `Float16` or `Uint8` datatype when the schema says so, refuses a dtype it has no vectors of when the `CollectionSchema` is built, and reads float64 as the float32 it actually stores, so a change between the two alone no longer recreates the collection (and drops every point). Valkey's `FT.CREATE` always declares `FLOAT32`, so a dtype change alone keeps the index.
- **Smaller fixes.** LanceDB's `_table_exists` reads every page of table names (the API pages at 100), so a table past the first page is not created again with `mode="overwrite"`. zvec's `ManagedConnection.open_or_create` drops a cached handle whose directory is gone instead of writing into deleted files.
- Docs for each check and the dtype behavior on the four connector pages.
